Task:
1. **Read the diff as its callers see it.** Read the code at the PR's own commits (`git show <sha>:<path>`, `git grep <pattern> <sha>`), never the working tree, which the session may move to the base or another head for its walks while you read. For every changed symbol (class, method, hook, template, Vue component, API handler or schema, migration, filter, CLI tool), grep its callers across the app and `lib/pkp`, and in the other apps where the change lands there too. For each, ask what the caller assumed before the change and whether that still holds: a changed return shape, a narrowed or widened condition, a default that moved, a null that is now possible, a removed hook, a column or setting renamed without its readers, a query that behaves differently on PostgreSQL. On the stable line the callers are 3.5's own: a backport written against `main` can meet a caller, a signature or a schema `main` no longer has, and what the backport changed to fit is where to look first.
2. **Walk every surface the change can reach**, not only the screen the PR was written for: user-visible flows in every role that reaches the code; the REST API (`api/v1` handlers, schemas, what a documented client receives); downstream exports and imports (native XML, JATS, Crossref, DataCite, DOAJ, PubMed and the other DOI or indexing plugins, OAI-PMH, sitemaps, citation formats, usage statistics); CLI tools under `tools/`; migrations and upgrade paths; scheduled and queued jobs; email templates; plugin hook points a third-party plugin would rely on. A label the change adds in English only, which other languages show as `##key##` until its translations arrive, is the team's translation process, not a regression: leave it out (@jarda.kotesovec, 2026-09-24).
3. **Read it for security**, new code as much as changed code, from the code alone. Ask these of every entry point the PR adds or changes (an API route, a page, a grid or form operation, an export or feed, a job), and of every check, filter or escape it removes:
   - Who can reach it, by this path and by every other path to the same data? Does it check as much as the routes beside it, and does every id taken from the request belong to the submission, context or user that was checked?
   - What does it return, and to whom? Every field, payload, file, log line and message, for each role that can call it.
   - What does it take from the request, and where does that go? Ids and parent ids, roles, file names, URLs, flags.
   - What does it print, in every format? Pages, components, emails, exports, links.
   - What did the change remove? A check, scope, filter or escape the old code had, a refactor included, or a fix one app has and the others lack.
   - Does every check run before the side effect, and refuse when its input is missing?
4. **Write every suspicion before you touch a fleet**, in `.reports/sync/{{agent}}/suspicions.md`, one block each: the surface, the app(s), the exact steps a person or client would take, expected (what worked before, with the pre-change code line, or for new code what should happen), suspected actual (with the post-change code line).

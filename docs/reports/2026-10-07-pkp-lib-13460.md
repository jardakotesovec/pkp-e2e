## Summary

A journal or preprint server gives each version its own DOI ("DOI
Versioning" "Yes") and assigns DOIs "Upon reaching the copyediting
stage" ("production" on a server). A manager creates a new major version
of a published work, which now gets new DOIs at once. Before that version
is published, the manager presses "Mark DOIs Registered" on the work, or
deposits it with Crossref. The new version's DOIs are marked
"Registered" too, although nothing sent them.

Once the version is published, its DOI stays "Registered" and no deposit
picks it up. The version goes public with a DOI the agency does not know,
so the DOI link does not resolve. Nobody is told. Depositing the work
again by hand after the publication sends it.

"DOI Versioning" is "Yes" by default on a preprint server and "No" on a
journal; the stage timing is the default on both.
Before this change, under that setting a new version got its DOIs only
on publication, so the mark could not reach it.

## Impact

- **Lost** The new version's DOI registration. The version is published
  with a DOI the agency never received, and the DOIs page reads
  "Registered" for it, so nobody looks again.
- **Who** Journals with "DOI Versioning" "Yes", and preprint servers in
  their default setup, that mark or deposit a work while a new major version of it
  waits unpublished. That means "Mark DOIs Registered" (journals that
  register outside OJS or OPS), "Deposit DOIs" on the work, or an
  automatic deposit that retries the work in that window.
- **Way round** "Deposit DOIs" on the work after the version is
  published sends it, as does "Mark DOIs Unregistered" and a new
  deposit. Neither is prompted: the page shows nothing wrong.

Medium: a published version's DOI never reaches the agency, silently,
but it needs a mark or a deposit of the work in the window between
creating a version and publishing it, and a deposit by hand afterwards
repairs it. It would be high if an ordinary automatic deposit ran in
that window; it reaches the work only when its current version's DOI
still needs a deposit.

coliforms isolated from nosocomial infections in a hospital in Isfahan,
Iran", is published with one version, 1.0. No agency is needed: "Mark
DOIs Registered" gives the DOIs the status an agency's answer to a
deposit gives them.

2. Open "Settings" › "Distribution" › "DOIs" › "Setup". Type `10.1234`
   in "DOI Prefix". Choose "Upon reaching the copyediting stage" under
   "Automatic DOI Assignment" and "Yes, assign a unique DOI to every
   version of an article." under "DOI Versioning". Press "Save".
3. Open "DOIs" › "Articles". Tick submission 17, choose "Bulk Actions" ›
   "Assign DOIs" and confirm "Assign DOIs". Version 1.0 gets its DOI.
4. Open submission 17's workflow and choose "Create New Version". Choose
   "Revision Significance" "Major Revision" and press "Confirm". The

5. Open "DOIs" › "Articles". Tick submission 17, choose "Bulk Actions" ›
   "Mark DOIs Registered" and confirm "Mark DOIs Registered".
6. Expand the work's row and press "View all" beside "There are 2
   versions.".
7. Back in the workflow, press "Publish" on version 2.0. In "Review
   Publishing Details" change nothing and press "Confirm", then confirm
   "Publish".
8. Open "DOIs" › "Articles", expand the work's row and press "View all".

On a preprint server (OPS `db0f597851`): submission 2, "The Facets Of Job
Satisfaction: A Nine-Nation Comparative Study Of Construct
Equivalence"; step 2 chooses "Upon reaching the production stage", and
"DOI Versioning" is already "Yes"; step 7 is "Post".

**Expected.** Step 6: only version 1.0's DOI reads "Registered". Version
2.0's reads "Unregistered", since nothing has sent it. Step 8: version
2.0's DOI still reads "Unregistered", so the next deposit sends it.

**Observed.** Step 6, the window "DOIs for all versions":


mark and after publication. With "DOI Versioning" "No", a major version
shares version 1.0's DOI and nothing new is made.

## Cause

Round 2 adds `WORKFLOW_STAGE_ID_DONE` to
`Repo::doi()->assignOnVersionCreation()` (lib/pkp
`classes/doi/Repository.php:366`). `AssignDOIs::handleVersioned()` calls
it when "Create New Version" fires `PublicationVersioned`. A work with a
published Version of Record stands at "Done", so under "Upon reaching
the copyediting stage" each new version of a published work now gets its
missing DOIs at creation. With "DOI Versioning" "Yes", a major version
starts with none (`version()` clears the publication's and the galleys'
`doiId`), so it gets new ones. The developer's summary of the PR states
this as intended.

The status updates were written for a submission whose DOIs were all
public. `PKPDoiController::markSubmissionsRegistered()` (lib/pkp
`api/v1/dois/PKPDoiController.php:601-606`) marks every id that
`Repo::doi()->getDoisForSubmission()` returns. OJS's and OPS's
implementations (ojs `classes/doi/Repository.php:188-218`, ops
`classes/doi/Repository.php:117-150`) loop over every publication,
published or not, with its galleys (and on OJS its completed reviews).
So the unpublished version's DOIs are marked "Registered", which breaks
the rule that a DOI reads "Registered" only once the agency has it.

A Crossref deposit marks the same set, while its XML holds published
versions only (code, not driven: no agency credentials):

- `depositSubmissions()` (`PKPDoiController.php:550-555`) marks every id
  of `getDoisForSubmission()` "Submitted" when it queues the deposit.
- After the agency answers, `CrossrefExportPlugin::updateDepositStatus()`
  (crossref-ojs `CrossrefExportPlugin.php:420-445`, crossref-ops
  `:469-490`) marks every id of `getDoisForSubmission()` "Registered",
  or "Error".
- The XML is built from published versions. OJS's
  `ArticleCrossrefXmlFilter` (`filter/ArticleCrossrefXmlFilter.php:86-99`)
  takes, with "DOI Versioning" "Yes",
  `Repo::doi()->getLatestMinorPublicationsForDoiDeposit()` (lib/pkp
  `classes/doi/Repository.php:436-459`): the publications with a DOI and
  status published, the latest minor of each stage and major. With "No"
  it takes the current publication. OPS's `PreprintCrossrefXmlFilter`
  (`filter/PreprintCrossrefXmlFilter.php:76-83`) takes every publication
  with a DOI and status published.

Nothing sends the DOI later. `getAllDepositableSubmissionIds()` (ojs
`classes/doi/DAO.php:37`), behind "Deposit All" and the automatic
deposit, takes the current published version's DOIs while
"Unregistered", "Error" or "Needs Sync". Publishing a major version is
meant to mark the work's DOIs "Needs Sync", which would bring it back,
but `publish()` compares the version with itself and never does
(`classes/publication/Repository.php:698-705`, pkp-e2e issue U45 A17).

The status updates over every version predate the PR. At the tips an
unpublished version carries a DOI only when someone types one in the
"View all" window's "Edit". Nothing assigns one automatically: there is
no `PublicationVersioned` listener, `VersionDois` assigns on
publication, and "Assign DOIs" takes the current version only. A
hand-typed DOI is marked the same way at the tips (code). Round 1 already
reached this under "Immediately", and for a version created at
Copyediting or Production. Round 2 makes it reach every new major
version of a published work under the default timing.

Reach:

- "Mark DOIs Registered" on the DOIs page: OJS and OPS, publication and
  galley DOIs (walked).
- "Deposit DOIs" with Crossref, and the automatic deposit when it
  deposits the work while the version waits (`depositAll()` runs the
  same job): OJS and OPS (code).
- OJS with DataCite: its `updateDepositStatus()` (`plugins/generic/datacite/DataciteExportPlugin.php:347-360`)
  takes the current version only, but "Deposit DOIs" has already marked
  the unpublished version's DOIs "Submitted", and they stay so (code).
- The export plugins' own "Mark registered": OJS
  `DOIPubIdExportPlugin::markRegistered()`
  (`classes/plugins/DOIPubIdExportPlugin.php:79-89`) and crossref-ops
  `CrossrefExportPlugin::markRegistered()` (`:496-505`) take the same
  set (code).
- OMP: not affected (walked). Its `getDoisForSubmission()` takes the
  current publication only (omp `classes/doi/Repository.php:120`), and
  it has no registration agency plugin.

## Proposed fix

Let the status updates that record what the agency has take only the
published versions' DOIs, the set the XML is built from. Give
`getDoisForSubmission()` an optional filter, in the abstract method
(lib/pkp `classes/doi/Repository.php:419`) and in the OJS, OMP and OPS
implementations:

```php
public function getDoisForSubmission(int $submissionId, bool $publishedOnly = false): array
{
    ...
    $publications = $submission->getData('publications');
    if ($publishedOnly) {
        $publications = $publications->filter(fn (Publication $p) => $p->getData('status') === Publication::STATUS_PUBLISHED);
    }
    // and the review DOIs read from these publications only
```

Pass `true` from `PKPDoiController::markSubmissionsRegistered()` and
`depositSubmissions()`, from `updateDepositStatus()` in crossref-ojs and
crossref-ops, and from the two export plugins' `markRegistered()`. Keep
the full set for "Mark DOIs Unregistered", "Needs Sync",
`AssignDOIs::handleDecline()` and `publish()`, which must reach every
version. Earlier published minor versions share their family's DOI row,
so the published set matches what the XML sends. This keeps round 2's
intent, a new version's DOIs from its creation.

**Alternatives**

- Drop `WORKFLOW_STAGE_ID_DONE` again (one line). This loses what round
  2 adds on purpose, and leaves the same fault under "Immediately" and
  for a hand-typed DOI.
- Have each plugin mark exactly the publications its XML filter chose.
  This is exact for Crossref, but the DOIs page's mark has no XML, so
  it still needs the filter above.
- Fix A17, so that publishing a major version marks the work's DOIs
  "Needs Sync". The next deposit would then send the version, but the
  page still reads "Registered" for an unpublished version until then.

**What goes with it**

- A unit test that "Mark DOIs Registered" and a deposit's status update
  leave an unpublished version's DOIs "Unregistered", and a U45 e2e
  scenario (the kept script below is its walk).
- No stored data to repair from this change (unmerged). DOIs typed by
  hand on unpublished versions and marked before cannot be told apart
  from registered ones, so no repair is proposed for them.
- The same calls are on `stable-3_5_0`; a backport would cover only the
  hand-typed case there.

Not tried: the checkouts stay at the PR heads for the rest of the
review, and the fix spans the two Crossref plugin repositories.

Medium: one optional argument in each app's `getDoisForSubmission()` and
six callers across pkp-lib, OJS and the two Crossref plugins, each a
line, with tests in several repositories.

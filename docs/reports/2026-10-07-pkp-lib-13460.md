## Summary

A press gives each version of a book its own DOI ("DOI Versioning"
"Yes") and has DOIs on for files. A manager creates a new major version
of a published book, which gets new DOIs at once, and then runs "Mark
DOIs Registered" on the book. The new version's file DOI ("PDF /
epilogue.pdf") reads "Registered" while the version is unpublished, and
still does after it is published. Its book and format DOIs correctly
stay "Unregistered".

Once two versions are published, "Mark DOIs Registered" marks the DOIs
of both, but "Mark DOIs Unregistered" resets only the newer version's.
The older version's book and format DOIs stay "Registered", and no bulk
action on the DOIs page resets them.

A press has no registration agency to send DOIs to, so nothing wrong
leaves the install. The statuses are the press's own record of what it
registered elsewhere, and they now say a file DOI is registered when
nobody registered it.

## Finding 1 — "Mark DOIs Registered" marks an unpublished new version's file DOI "Registered"

- **Severity** low
- **Effort** small
- **Kind** regression
- **Affects**
  - main: OMP, once the PRs merge
  - 3.5: none (code; no "DOI Versioning" on a press)
  - 3.4: none (code)
  - 3.3: none (code; no DOI statuses)

### Impact

- **Lost** A correct status for the new version's file DOI. It reads
  "Registered" before anything registered it, and keeps reading so once
  the version is published. Nobody is told.
- **Who** Presses with "Files" ticked under "Items with DOIs" (off by
  default) and "DOI Versioning" "Yes" (also off by default), that mark
  a book registered while a new major version of it waits unpublished.
- **Way round** "Mark DOIs Unregistered" on the book after the version
  is published resets the file DOI. The page shows nothing wrong, so
  nothing prompts it.

Low: nothing is sent to an agency and the book and format DOIs are
right. It would be medium for a press that registers its file DOIs by
hand and reads this page to see which still need it, since the new
version's file DOI would then never be registered.

### Steps to reproduce

Preconditions: PKP's default test dataset for `main` (OMP), the PRs
checked out (omp `e4cab0c9e9`, lib/pkp `68d984c2c9`). The press has DOIs
on for "Monographs" only, no prefix and no registration agency. Book 5,
"Bomb Canada and Other Unkind Remarks in the American Media", is
published as version 1.0, with the format "PDF" holding the file
"epilogue.pdf".

1. Sign in as `dbarnes` (password `dbarnesdbarnes`).
2. Open "Settings" › "Distribution" › "DOIs" › "Setup". Tick
   "Publication Formats" and "Files" under "Items with DOIs" beside
   "Monographs". Type `10.1234` in "DOI Prefix". Keep "Upon reaching the
   copyediting stage" under "Automatic DOI Assignment" and choose "Yes,
   assign a unique DOI to every version of a monograph/chapter." under
   "DOI Versioning". Press "Save".
3. Open "DOIs" › "Monographs". Tick book 5, choose "Bulk Actions" ›
   "Assign DOIs" and confirm "Assign DOIs". Version 1.0's book, format
   and file get their DOIs.
4. Open book 5's workflow and choose "Create New Version". Choose
   "Revision Significance" "Major Revision" and press "Confirm". The
   workflow opens version 2.0, unpublished, which has DOIs of its own.
5. Open "DOIs" › "Monographs". Tick book 5, choose "Bulk Actions" ›
   "Mark DOIs Registered" and confirm "Mark DOIs Registered".
6. Expand the book's row and press "View all" beside "There are 2
   versions.".
7. Back in the workflow, press "Publish" on version 2.0 and confirm
   "Publish". Open "DOIs", expand the book's row and press "View all".

**Expected.** Step 6: only version 1.0's DOIs read "Registered". Every
DOI of version 2.0 reads "Unregistered", since it is not published and
nothing registered it. Step 7: the same for 2.0's DOIs.

**Observed.** Step 6, the window "DOIs for all versions":

```
Version of Record 2.0 Unpublished
  Monograph            10.1234/bq4z2v06   Unregistered
  Format / PDF         10.1234/m8anbm73   Unregistered
  PDF / article.pdf    10.1234/0k1pt346   Registered
```

Version 1.0's three rows read "Registered". Step 7: version 2.0's file
DOI still reads "Registered", its book and format DOIs "Unregistered".

### Cause

Round 3 adds `Repo::doi()->getPublishedDoisForSubmission()` (lib/pkp
`classes/doi/Repository.php:435`). It collects
`getDoisForPublication()` for each published version, and
`PKPDoiController::markSubmissionsRegistered()` (lib/pkp
`api/v1/dois/PKPDoiController.php:602`) marks that set.

OMP's `getDoisForPublication()` (omp `classes/doi/Repository.php:215-219`)
reads the files with `filterBySubmissionIds([submissionId])` and the
proof stage: every proof file of the book, whichever version's format
holds it. So 1.0's set carries 2.0's file, and the mark breaks the rule
that a DOI reads "Registered" only for a published version. The
monograph, chapter and format DOIs are read from the publication itself
and are right.

The lookup by book predates the PR: it was written for
`getDoisForSubmission()` in 2021 (`:154-158`) and copied into
`getDoisForPublication()` in 2025. At the tips the status actions read
the same set both ways, and a new major version's files got their DOIs
only on publication (`VersionDois`) or through "Assign DOIs" (Reach), so
the lookup showed no harm that was seen.
Round 2 gives a new version its DOIs at creation
(`assignOnVersionCreation()`), and round 2's mark (`getDoisForSubmission()`:
the current version plus every proof file) already reached 2.0's file
the same way (code; round 2's walk did not tick "Files").

Reach:

- "Mark DOIs Registered" on the DOIs page (walked).
- "Deposit DOIs" marks the same set "Submitted" (`depositSubmissions()`,
  `PKPDoiController.php:552`), but a press has no agency plugin to offer it (code).
- `createDois()` in omp `classes/publication/Repository.php:571` and
  `classes/submission/Repository.php:122` finds files the same way, so
  assigning a version's DOIs gives every version's files a DOI. At the
  tips "Assign DOIs" on a published 1.0 would give an unpublished 2.0's
  files theirs (code, not driven).
- The stale marks after publishing and unpublishing
  (`getDoisForPublication()`, lib/pkp `classes/publication/Repository.php:719-841`)
  reach every version's files; they touch only "Submitted" and
  "Registered" DOIs (code).
- OJS and OPS read galleys from the publication and are not affected.

### Proposed fix

Read a publication's files through its own formats, as OMP's
`publication\Repository::version()` already does when it copies them
(`filterByAssoc(Application::ASSOC_TYPE_REPRESENTATION, [...])`, `:157-164`).
In omp `classes/doi/Repository.php` `getDoisForPublication()`:

```diff
             $submissionFiles = Repo::submissionFile()
                 ->getCollector()
                 ->filterBySubmissionIds([$publication->getData('submissionId')])
+                ->filterByAssoc(
+                    Application::ASSOC_TYPE_REPRESENTATION,
+                    collect($publication->getData('publicationFormats'))->map(fn ($f) => $f->getId())->values()->all()
+                )
                 ->filterByFileStages([SubmissionFile::SUBMISSION_FILE_PROOF])
                 ->getMany();
```

A publication without formats then gets no files (`whereIn` on an empty
list matches nothing). Make the same change in the loop of
`getDoisForSubmission()` and in the two `createDois()`, so that every
lookup of "this version's files" agrees. With finding 2's fix the
status actions then reach each version's files through that version.

**Alternatives**

- Filter the published set in pkp-lib by the DOI's owner. pkp-lib does
  not know OMP's files; the rule lives in OMP's class.
- Leave `createDois()` alone. It only mints missing DOIs, but it is the
  same mistake, and it gives an unpublished version's files DOIs ahead of
  the version.

**What goes with it**

- A unit test that `getDoisForPublication()` of 1.0 leaves out 2.0's
  file, and the kept script below as the e2e walk.
- No stored data to repair from this change (unmerged).

Not tried: the checkouts stay at the PR heads for the rest of the
review.

Small: a few lines in OMP's DOI class following `version()`'s pattern,
the same lines in two `createDois()`, and a unit test.

## Finding 2 — "Mark DOIs Unregistered" does not reset an older version's DOIs that "Mark DOIs Registered" marked

- **Severity** low
- **Effort** small
- **Kind** regression
- **Affects**
  - main: OMP, once the PRs merge
  - 3.5: none (code; both actions read the same set)
  - 3.4: none (code)
  - 3.3: none (code; no DOI statuses)

### Impact

- **Lost** The undo. A mark the press did not mean, on a book with two
  published versions, leaves the older version's book and format DOIs
  "Registered" after "Mark DOIs Unregistered".
- **Who** Presses with "DOI Versioning" "Yes" and a book published in
  more than one major version, that mark the book and then unmark it.
- **Way round** Unpublish the newer version, so the older one is the
  book's current version, run "Mark DOIs Unregistered", and publish the
  newer one again. Nothing on the page suggests it.

Low: nothing is sent anywhere and nothing is lost but a status, which a
roundabout way sets right.

### Steps to reproduce

Preconditions as finding 1, through step 3 (book 5 with its 1.0 DOIs).

1. Open book 5's workflow and choose "Create New Version". Choose
   "Revision Significance" "Major Revision" and press "Confirm".
2. Press "Publish" on version 2.0 and confirm "Publish".
3. Open "DOIs" › "Monographs". Tick book 5, choose "Bulk Actions" ›
   "Mark DOIs Registered" and confirm it.
4. Tick book 5, choose "Bulk Actions" › "Mark DOIs Unregistered" and
   confirm it.
5. Expand the book's row and press "View all".

**Expected.** Step 5: every DOI the mark at step 3 set reads
"Unregistered" again.

**Observed.** After step 3 all six DOIs read "Registered". Step 5:

```
Version of Record 1.0 (2026-10-07)
  Monograph            10.1234/2z17m141   Registered
  Format / PDF         10.1234/n9kr2306   Registered
  PDF / article.pdf    10.1234/gh2rvf67   Unregistered
Version of Record 2.0 (2026-10-07)
  Monograph, Format / PDF, PDF / article.pdf   Unregistered
```

Unpublishing 2.0 and running "Mark DOIs Unregistered" again resets
1.0's DOIs.

### Cause

Round 3 moves "Mark DOIs Registered" to `getPublishedDoisForSubmission()`,
every published version. "Mark DOIs Unregistered" and "Mark DOIs Needs
Sync" stay on `getDoisForSubmission()` (lib/pkp
`api/v1/dois/PKPDoiController.php:655`, `:708`). On OJS and OPS that is
every version, a superset of the mark. OMP's reads the current version
only (omp `classes/doi/Repository.php:120`), plus every proof file by
book, so the two actions on a press now reach different sets.

At the tips and in round 2 both actions read OMP's
`getDoisForSubmission()`, so the press could mark only the current
version but every mark could be undone. Round 3 widens the
mark only.

Reach:

- "Mark DOIs Unregistered" (walked) and "Mark DOIs Needs Sync" (code).
- Publishing a major version, meant to mark every DOI of the book "Needs
  Sync", reads the same method (lib/pkp
  `classes/publication/Repository.php:704`); that branch never runs
  today (U45 A17).

### Proposed fix

Let OMP's `getDoisForSubmission()` read every version, as OJS's and
OPS's do:

```diff
-        $publications = [$submission->getCurrentPublication()];
+        $publications = $submission->getData('publications');
```

This is the OMP half of the fix proposed for U45 A17 (pkp-e2e#229), tried
there on `main` for the "Needs Sync" mark. The press can then mark,
unmark and flag every version's DOIs, as a journal can.
With finding 1's fix the file query in the loop reads each version's own
files.

**Alternatives**

- Override `getPublishedDoisForSubmission()` in OMP to return the current
  version only. The mark then matches the unmark again, but the press
  still cannot mark an older version's DOIs, as at the tips.
- Have the unmark and "Needs Sync" read `getPublishedDoisForSubmission()`
  too. On a journal and a preprint server they would then miss an
  unpublished version's DOIs, which they reach today.

**What goes with it**

- "Mark DOIs Unregistered", "Needs Sync" and a decline under
  "Immediately…" (which returns early once a version is published)
  reach every version on a press, as on a journal. Under "DOI
  Versioning" "No" the versions share their DOIs, so nothing changes.
- A unit test that the unmark resets what the mark set, and the kept
  script below.

Not tried at the round-3 heads: the checkouts stay at the PR heads.

Small: one line in OMP's DOI class, already tried for A17, and a test.

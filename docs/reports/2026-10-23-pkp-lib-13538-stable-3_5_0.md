## Summary

On 3.5, someone invited to a role who has no account goes through the
invitation's steps: "Verify ORCID iD", "Create OJS account", "Enter
details", "Review & create account". If they skip ORCID, fill in
"Create OJS account" (username, password, the privacy consent), and then
go back to the first step and connect their ORCID iD after all, the page
returns to "Create OJS account". The password field still shows what
they typed and the consent box is still ticked, but the page has
forgotten both.

"Save and continue" then refuses with "Please confirm that you have read
and agree privacy statement" under the ticked box. Unticking and ticking
the box again gets one step further, then the page shows "The password
field cannot be null." under a password field that still looks filled.
They can only go on by typing the password again.

Before this change the same steps kept the password and the consent, and
"Save and continue" moved on to "Enter details". The ORCID iD is saved
in both cases.

## Impact

- **Lost**: the password and privacy consent the invitee already
  entered. The screen keeps showing them, so the error messages
  contradict what the invitee sees.
- **Who**: new users accepting a role invitation in a journal, press or
  server with ORCID enabled, who skip ORCID at first and then go back
  for it. Every 3.5 install that takes the next patch release, until
  this is fixed.
- **Way round**: on screen. Untick and tick the consent box again, and
  type the password again.

Medium: the invitee can still finish, but the page misleads them, and
only on a path a few invitees take. It would be higher if the invitee
could not find the way round.

## Steps to reproduce

Preconditions: a fresh OJS 3.5 install at the `stable-3_5_0` tip (OMP
and OPS behave the same), with an ORCID sandbox client. Mail is
readable (the invitation email is needed).

1. As the Journal Manager, Settings › Users & Roles › "ORCID": tick
   "Enable ORCID functionality", choose the public sandbox API, enter the
   sandbox client's ID and secret, and Save.
2. Users & Roles › "Users" › "Invite to a role": enter an email address
   that has no account, give it the "Reviewer" role with a start date,
   and send the invitation.
3. Signed out, open the email's link to accept. The page shows
   "STEP 1 - Verify ORCID iD".
4. Press "Skip ORCID verification".
5. On "STEP 2 - Create OJS account", fill in "Username" and "Password",
   tick "Yes, I agree to have my data collected and stored according to
   the Privacy Statement", and press "Save and continue". The page shows
   "STEP 3 - Enter details".
6. Press "Back", then "Back" again, to return to "STEP 1 - Verify ORCID
   iD".
7. Press "Verify ORCID iD", sign in to the ORCID sandbox in the window
   that opens, and authorize. The window closes and the page shows
   "STEP 2 - Create OJS account", with the username, the password (as
   dots) and the ticked box.
8. Press "Save and continue".

**Expected** (as at the previous 3.5 tip): the page moves on to "STEP 3
- Enter details".

**Observed**: the page stays on step 2 and shows "Please confirm that you
have read and agree privacy statement" under the ticked box. Untick the
box, tick it again, and press "Save and continue". The page now shows
"The password field cannot be null." under the password field, which
still shows its dots. Only after the password is typed again does it
move on.

## Cause

`AcceptInvitationVerifyOrcid.vue` used to take the ORCID data the
callback window sent (`addOrcidInvitationData`) and write only the ORCID
fields into the page's payload (`setOrcidData()`), then go to the next
step. Now the server stores the ORCID data itself, and the callback only
says it is done (`orcidAddedToInvitation`). The page's handler,
`orcidAdded()`, calls the store's `receiveInvitation()` to read the
iD back:

```js
async function orcidAdded() {
	await store.receiveInvitation();
	nextStepWithoutRefine();
}
```

`receiveInvitation()` in `AcceptInvitationPageStore.js` is the
page-load initializer. Besides the ORCID fields it resets the account
fields to their starting values:

```js
updateAcceptInvitationPayload('privacyStatement', userId.value ? true : false);
updateAcceptInvitationPayload('username', data.value.username);
updateAcceptInvitationPayload('password', null);
```

For a new user, the consent is set to false and the password to null.
The form fields on "Create OJS account" keep showing what was typed, so
the screen and the payload disagree. The `privacyStatement` check in
`nextStep()` then refuses, and once that box is ticked again, `refine`
is sent `"password": null` and answers 422.

## Proposed fix

After ORCID, re-read only what ORCID changed. For example, give
`receiveInvitation()` a flag (or add a small `refreshOrcid()`) that,
after the fetch, updates `orcid` and `orcidIsVerified` alone and leaves
the account fields as the invitee left them:

```js
async function orcidAdded() {
	await store.refreshOrcid(); // fetches the invitation, sets orcid and orcidIsVerified only
	nextStepWithoutRefine();
}
```

One file in ui-library, plus a store test for "going back to ORCID keeps
the typed account fields". Not tried.

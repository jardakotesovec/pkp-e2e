# An abstract that names HTML tags as text comes out of the article's JATS XML with those names turned into real markup

Regression. OJS at `38781720df` (lib/pkp `f8bacd7658`); introduced by
pkp/ojs#5813 (`325931a71c`, 2026-09-21: `plugins/generic/jatsTemplate`
`c1c0e5379f..1065bb02ae`, for pkp/pkp-lib#12356). OMP and OPS: not
affected, the plugin ships in OJS alone. stable-3_5_0: shows it in
titles since pkp/ojs#5827 (`4a76983529`, 2026-09-24) at `a3dc3b54ff`; 3.5's
JATS has no abstract. Upstream: pkp/pkp-lib#13378 (the abstract case).
Tracked in `docs/tracking/ci-triage.md` "Open regressions". Temporary: delete once acted on.

**Update 2026-09-25: titles, and stable-3_5_0.** The same conversion
builds the JATS titles (article title, subtitle, translated title and
subtitle): a title typed as "The <i>species</i> element in HTML" in
"Title & Abstract" comes out as
`<article-title xml:lang="en">The <italic>species</italic> element in HTML</article-title>`.
On `main` titles have gone through it since jatsTemplate `be30f06`
(pkp/pkp-lib#12946, 2026-07-08), before this report's change. On
`stable-3_5_0` it is new with pkp/ojs#5827, which ported `JatsHelper` for
the titles (before it, 3.5 kept the words as text); 3.5's JATS carries no
abstract, so the titles are all it shows there. Either proposed fix below
covers the titles on both branches. A second 3.5-only finding in the
same port (a title with a bare "<" cut off) is its own report,
`docs/reports/2026-09-25-ojs-5827-stable-3_5_0.md`.

## Summary

An article's default JATS XML (the "JATS XML" page under Publication, its
"Download", and the OAI-PMH `jats` format) is built from the abstract.
Since the jatsTemplate update of 2026-09-21, an abstract whose text
mentions tags by name with a matching close tag, as an article about HTML,
XML or JATS would ("write <i>species names</i> in italics", "<p>text</p>
is a paragraph"), comes out with those names turned into markup: the words
between them are italicised, the sentence is cut into paragraphs, and the
tag names are gone from the text. Before the update the JATS carried the
author's sentence as typed.

## Impact

Editors and authors of articles that discuss markup (a narrow set: papers
on HTML, XML, JATS, templating, screen readers). What they lose is the
abstract's own words in every JATS consumer: the "JATS XML" page and its
download, the OAI-PMH `jats` record a harvester or the PubMed Central
export takes, and nothing warns, because the result is well-formed and
valid JATS. The article's landing page and the abstract as stored are
untouched. No workaround short of rewriting the abstract without tag
names; uploading a hand-made JATS file replaces the default document.
Minor: a narrow input class, output only, and silent.

## Steps to reproduce

Preconditions: a fresh install with its default languages; one journal;
one submission at any stage (the JATS page exists on every submission's
workflow); a Journal Manager account.

1. Sign in as the Journal Manager, open the submission's workflow and
   press "Publication" › "Title & Abstract".
2. In "Abstract", type as plain text, angle brackets included:
   `Write <i>species names</i> in italics and H<sub>2</sub>O with a
   subscript; a <br> tag breaks the line and <p>text</p> is a paragraph.`
   The editor shows the brackets as typed. Press "Save".
3. Press "JATS XML" in the same side menu and read the `<abstract>` in
   the document shown, or press "Download" and open the file.

Expected (the behavior before the change): one paragraph holding the
sentence as typed:

```xml
<abstract>
  <p>Write &lt;i&gt;species names&lt;/i&gt; in italics and H&lt;sub&gt;2&lt;/sub&gt;O with a subscript; a &lt;br&gt; tag breaks the line and &lt;p&gt;text&lt;/p&gt; is a paragraph.</p>
</abstract>
```

Observed, on OJS: two inline elements and four paragraphs, the tag names
gone:

```xml
<abstract>
  <p>Write <italic>species names</italic> in italics and H<sub>2</sub>O with a subscript; a</p>
  <p>tag breaks the line and</p>
  <p>text</p>
  <p>is a paragraph.</p>
</abstract>
```

The same document is served by "Download", by
`GET /api/v1/submissions/{id}/publications/{pid}/jats` and by the OAI-PMH
`jats` record once the article is published. Control: the same sentence
with a tag name that has no closing partner (only "<i>", no "</i>") comes
through as typed, because that document fails to parse and the plugin
falls back to plain text.

## Cause

`plugins/generic/jatsTemplate/classes/JatsHelper.php`,
`htmlToJatsContent()`: `strip_tags()` keeps the allowed tags,
`html_entity_decode()` then turns the stored literal `&lt;i&gt;` into
`<i>`, `htmlspecialchars()` re-escapes the real tag and the former text
to the same `&lt;i&gt;`, and `convertEscapedTags()` maps every one to
`<italic>`; the literal `&lt;br&gt;` becomes the `<break/>` marker and the
literal `&lt;p&gt;` a paragraph boundary, which `normalizeParagraphs()`
turns into the four `<p>` elements. The deleted `xsl/htmlAbstractToJats.xsl`
path parsed the stored HTML with `loadHTML()`, where an entity is a text
node, and re-escaped text with `value-of`, so a tag name in the text never
became a tag. The old `JatsHelper::htmlToJatsElement()` already had the
decode-then-map order for `bio`, `fn` and `notes`; the abstract, the plain
language summary and the new data availability section meet it with this
update. A balanced literal tag yields XML the parser accepts; an
unbalanced one fails `appendXML()` and the plain-text fallback re-reads
the stored HTML with `strip_tags()` alone, which leaves entities as they
are.

## Proposed fix

A proposal; the team decides.

1. Convert from the parsed HTML rather than from the string: load the
   stored HTML into a `DOMDocument` (as the stylesheet did), walk the
   nodes, map element nodes to their JATS elements and escape text nodes.
   A text node that reads "<i>" stays text. Covers `bio`, `fn` and
   `notes` too. A rewrite of `htmlToJatsContent()`; the tests under
   `tests/functional/JatsHelperTest.php` already pin the intended shapes.
2. Or, smaller: protect the real tags before decoding, by replacing each
   allowed tag with a placeholder, decoding and escaping the rest, then
   restoring the placeholders as JATS, so a literal `&lt;i&gt;` never
   reaches `convertEscapedTags()`. Same coverage, less change, one more
   pass over the string.

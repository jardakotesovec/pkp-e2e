## Finding 1 — No "Discussion (…)" template to fall back on: the message is not emailed and the window fails

### Impact

- **Lost**: the email. The discussion holds the message and the
  recipient sees it in the app, but nothing reaches their inbox. The
  window stays open with the text and says nothing. An editor who
  presses again opens a duplicate discussion. On "Assign", the person
  is assigned anyway.
- **Who**: an editor or manager on a stage whose "Discussion (…)"
  template a manager deleted under Settings › Workflow › "Tasks and
  Discussions" (that screen allows it). A fresh install has the template
  on every stage.
- **Way round**: choose another predefined message and replace its
  text, or write in the discussion from the stage's discussions panel.

Medium: a task fails with a server error, and the editor gets no
feedback. The state is rare (a deleted default), and there is a way
round on screen.

### Steps to reproduce

Preconditions:
- A fresh OJS install with a journal, its Journal Manager, a Section
  editor and an author.
- A submission in the Submission stage.

1. Sign in as the Journal Manager and open Settings › Workflow › "Tasks
   and Discussions".
2. In "Submission Stage", open the row menu of "Discussion (Submission)"
   and choose "Delete", then "OK".
3. Open the submission's Submission stage.
4. In "Participants", open the author's row menu and choose "Notify".
5. Leave "Choose a predefined message to use, or fill out the form
   below." on its blank entry, type "Please check the files." in
   "Message" and press "Notify".
6. Press "Assign", choose the Section editor, leave the list blank, type
   a message and press "OK".

**Expected**: the message is sent as "Discussion (Submission)", as it is
on a stage that still has the template, and the window closes with
"Notification sent to users.".

**Observed**: both windows stay open as filled, with no notice. No email
arrives. The discussions panel lists a new "Discussion (Submission)" for
each attempt, with the typed message. The author and the Section editor
each get a new-discussion notification, and the Section editor is
assigned. Both requests answer 500:

```
PHP Fatal error:  Uncaught BadMethodCallException: Call to undefined method PKP\mail\Mailable@anonymous in lib/vendor/laravel/framework/src/Illuminate/Support/Traits/ForwardsCalls.php:67
```

The same happens on OMP (Submission) and OPS (Production).

### Cause

When no template is found, `PKPStageParticipantNotifyForm::sendMessage()`
now builds `new class extends Mailable { use Sender; use Recipient; }`.
It then creates the discussion, its participants, the head note and the
notification, and calls `$mailable->allowUnsubscribe($notification)`.
That method comes from the `Unsubscribe` trait, through `Discussion`,
which `TemplateVariables` uses and the anonymous class does not. Laravel's
`Mailable::__call()` throws. Everything written before the call stays;
the email and the log entry never happen.

### Proposed fix

A proposal; the team decides. Build the fallback as a
`TemplateVariables` from the discussion the form has just created, so it
carries the `Discussion` trait (the unsubscribe footer included) and the
submission variables:

```php
// Create a query
$query = EditorialTask::create([... unchanged ...]);

// Without a template, the discussion just created describes the message.
$mailable = new TemplateVariables($template ? $template->promote($submission) : $query, $submission, $context);
$mailable
    ->addData(['authorName' => $recipient->getFullName()])
    ->sender($sender)
    ->recipients([$recipient])
    ->body($this->getData('message'))
    ->subject($this->getDiscussionTitle($template));
```

This means moving the mailable block below `EditorialTask::create()`
and dropping the anonymous class and its three new `use` lines. Tried
on OJS: both windows close with their notices. The author and the
Section editor each get a "Discussion (Submission)" email with the typed
text and the discussion footer ("Reply to this comment at … or
unsubscribe …"), and each attempt opens one discussion.

Small: one block moved in one method.

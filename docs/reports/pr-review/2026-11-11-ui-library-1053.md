## Summary

The PR links each in-text citation of the Body Text to its reference in
"Export to HTML", "Preview: PDF" and "Create PDF". The links work, but the
numbers readers see do not match the list they lead to. The exported
"References" section holds only the cited references, without numbers,
while each citation's number is the reference's place in the version's
full References list. A text that cites the 2nd and 4th of four references
reads "[2]" and "[4]" above a list of two unnumbered entries. A printed
PDF cannot follow the links, so a reader of "[4]" cannot tell which entry
is meant.

The same renumbering overwrites text an editor typed over a citation when
that text is a number. A citation set to "(2021)" in "Selected Element"
(the author–year form, "Smith (2021)") is published as "Smith (2)".
Before the PR the export never changed a citation's text.

## Impact

- **Lost**: a correct published text. The HTML and PDF galleys show
  citation numbers that match no visible list, and typed years are
  silently replaced with list numbers. Nobody is told; the editor still
  shows its own numbers ("[10]", "(2021)").
- **Who**: every OJS journal that uses the Body Text editor's export with
  in-text citations, as soon as the version has a reference that is not
  cited, or a citation whose typed text is a number in brackets or
  parentheses. Readers of the published galleys meet it.
- **Way round**: cite every reference of the version, or none; there is
  none for typed years except writing them outside the citation.

Medium: a published output is wrong for the citations it holds, silently,
on an ordinary setup; the links still lead to the right entry on screen,
which keeps it from high.

A third, smaller effect of the same section: after "Export to HTML", the
"JATS XML" page's generated XML ends its `<body>` with "References" and the
cited references, which `<back><ref-list>` already holds (low).

## Steps to reproduce

Preconditions: PKP's default dataset, OJS `main`, with the three PRs'
heads checked out and built.

1. Sign in as `dbarnes` and open submission 15, "Yam diseases and its
   management in Nigeria" (Production).
2. Under the version, open "References" and add four references, one
   per "Add": "Alpha, A. (2020). First reference.", "Beta, B. (2021).
   Second reference.", "Gamma, G. (2022). Third reference.", "Delta, D.
   (2023). Fourth reference.".
3. Open "Body Text". Type "First sentence cites Beta.", press Enter and
   type "Second sentence cites Delta.".
4. In the side panel's "References", drag "Beta, B. …" to the end of the
   first sentence and "Delta, D. …" to the end of the second. The editor
   shows each citation with the number the panel shows beside the
   reference, for example "[10]" and "[12]".
5. Drag "Beta, B. …" again, at the end of a third sentence "Fourth
   sentence: Beta", click that citation, open "Selected Element", set
   "In-text citation" to "(2021)", press "Update".
6. Press "Save", then "Export" › "Export to HTML".
7. Open "Galleys" and the "HTML" galley (or "Export" › "Preview: PDF").

**Expected**: the citations' numbers match a numbered "References" list
at the end ("[1]" Beta, "[2]" Delta), as the issue's example shows with
`<ol><li id="ref-123">`, and the typed "(2021)" stays "(2021)".

**Observed**:

```
First sentence cites Beta.[2]
Second sentence cites Delta.[4]
Fourth sentence: Beta (2).

References
Beta, B. (2021). Second reference.
Delta, D. (2023). Fourth reference.
```

"[2]", "[4]" and "(2)" are links to the right entries (`#body-text-ref-<id>`),
and the "PDF" galley carries the same links as annotations. A citation
to both ("[10, 12]" in the editor) is exported as "[2, 4] (Reference 2;
Reference 4)" (U48 A28). Control: with every reference cited, the numbers
happen to match the list's order.

## Cause

`src/components/BodyTextEditor/bodyTextReferenceExport.js`,
`exportBodyTextReferences()`:

- `referenceNumbers` is built from every reference of the version
  (`[...referenceById.keys()].map((id, index) => [id, index + 1])`), but
  the section it links to is built from `orderedIds`, the cited ones
  only, and its entries are `<p>` elements with no number. So the number
  counts references the reader never sees.
- The marker is rewritten when `!items.some((item) => item.locator ||
  item.prefix || item.suffix)`, and `updateNumericCitationMarker()`
  rewrites any text that is digits alone, bare or in brackets or
  parentheses. Nothing checks that the digits are the editor's own
  marker (`[${id}]`, from `@sciflow/editor-core`'s drop and insert
  commands) rather than text the editor typed, nor the citation's
  `data-citation-mode="custom"`, though the comment above says "leave
  custom text … alone".

The same file's section is what `ArticleBody.php` (jatsTemplate) reads
into the JATS `<body>`, so the cited references land there too.

## Proposed fix

In `exportBodyTextReferences()` (the one place every export passes
through):

1. Number the exported references from `orderedIds`, after it is built,
   so "[n]" is the entry's place in the exported list, and prefix each
   entry with `<span class="body-text-reference-number">[n] </span>` so
   the list shows the numbers (this also numbers entries that come from
   the document's own bibliography).
2. Rewrite a marker only when its digits are the cited ids, as the editor
   writes them, and never in `custom` mode: pass the ids to
   `updateNumericCitationMarker()` and return when `marker.match(/\d+/g)`
   differs from them (for a range, its two ends against the first and
   last id).

The diff is `shared/playwright/checks/sync/ui-library-1053/fix.diff`
(relative to the OJS root, 41 changed lines in that one file). Tried
2026-11-11 on OJS at the PR heads with the kept drive: the galley, the
preview and the PDF read "[1]", "[2]", "[1, 2]" and "(2021)" above
"[1] Beta, B. …", "[2] Delta, D. …", the PDF with 5 link annotations; the
deleted-reference refusal (U48 A27) unchanged.

Alternatives: list every reference of the version, numbered, instead of
the cited ones (keeps the PR's numbers, but publishes references the text
never cites); render the section as `<ol>` (as the issue's example)
instead of the number spans (cleaner HTML, but an imported bibliography's
`<p>` entries would then need moving into the list). A unit test of
`exportBodyTextReferences()` with an uncited reference and a typed year
would have caught both. The JATS duplicate is the jatsTemplate's to
decide (drop `.body-text-references` from the body, since `<back>` has
the references), not part of this fix.

Small: one file in ui-library, plus a unit test.

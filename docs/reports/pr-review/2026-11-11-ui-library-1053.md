## Summary

The editor writes each citation as the reference's database id ("[117]",
the number the side panel prints beside the reference). The export turns
it into the reference's number in the list ("[4]") only when the
citation's text is that bare marker and the citation is not `custom`.
Two ordinary edits leave the id in the text and stop that rewrite, so the
galley publishes the database id:

- **Text typed on after a citation.** When a citation ends a paragraph,
  the caret after End sits inside the citation (its text is editable
  in place). An editor who drops a citation at a sentence's end and
  keeps typing writes into the citation, " More text 2020." included. The
  galley shows "[114] More text 2020." as one link, beside "1. Alpha …"
  in the list.
- **A page added in "Selected Element".** Setting "In-text citation" to
  "[117, p. 5]" makes the citation `custom`, and the export keeps it
  whole. The galley shows "[117, p. 5]" while the other citations to
  the same reference read "[4]", above "4. Delta …".

## Impact

- **Lost**: a correct published text. The HTML and PDF galleys show an
  internal database id as a citation number that matches no entry of
  the numbered list. In the first case the following sentence is part of
  the citation's link too. Nobody is told; the editor shows the same id
  everywhere, so nothing looks wrong there.
- **Who**: every OJS journal that uses the Body Text editor's export,
  as soon as an editor writes on after a paragraph-final citation, or
  adds a page to a citation ("[12, p. 5]", common in the humanities).
  Readers of the published galleys meet it.
- **Way round**: start a new paragraph instead of typing after a final
  citation, and type the list number yourself when adding a page. The
  editor never shows that number: it shows the id.

Medium: a published output is silently wrong on ordinary edits; the link
still leads to the right entry on screen, which keeps it from high.

Unchanged from round 1 (low): after "Export to HTML", the "JATS XML"
page's generated XML ends its `<body>` with "References" and the cited
references, which `<back><ref-list>` already holds.

## Steps to reproduce

Preconditions: PKP's default dataset, OJS `main`, with the three PRs'
round-3 heads checked out and built.

1. Sign in as `dbarnes` and open submission 15, "Yam diseases and its
   management in Nigeria" (Production).
2. Under the version, open "References" and add four references:
   "Alpha, A. (2020). First reference.", "Beta, B. (2021). Second
   reference.", "Gamma, G. (2022). Third reference.", "Delta, D. (2023).
   Fourth reference.". The side panel of "Body Text" shows each with its
   id, for example 114 to 117.
3. Open "Body Text", type "Typed on: Alpha." and drag "Alpha, A. …" to
   its end: "[114]". Click the start of that paragraph, press End and
   type " More text 2020.".
4. Press Enter, type "Page cites Delta." and drag "Delta, D. …" to its
   end. Click that citation, open "Selected Element", set "In-text
   citation" to "[117, p. 5]" and press "Update".
5. Press Enter, type "Plain cites Delta." and drag "Delta, D. …" to its
   end.
6. Press "Save", then "Export" › "Export to HTML", and open the "HTML"
   galley (or "Export" › "Preview: PDF").

**Expected**: "[1] More text 2020." with the link on "[1]" only,
"[4, p. 5]" and "[4]", above "1. Alpha …" and "4. Delta …".

**Observed** (the drive's run `r3head`):

```
Typed on: Alpha.[114] More text 2020.     (all of it one link, "Reference 1")
Page cites Delta.[117, p. 5]               (link, "Reference 4")
Plain cites Delta.[4]

References
1. Alpha, A. (2020). First reference.
4. Delta, D. (2023). Fourth reference.
```

In the editor after step 3, the paragraph is `Typed on: Alpha.<cite …>[114] More text 2020.</cite>`.

## Cause

`src/components/BodyTextEditor/bodyTextReferenceExport.js`,
`exportBodyTextReferences()`:

- `updateNumericCitationMarker()` rewrites a citation only when its
  whole text is numbers alone, bare or in brackets or parentheses, and
  only when it is not `custom` and has no locator, prefix or suffix. Any
  other text is kept whole, including the id the editor wrote at its
  start (`[${id}]`, `@sciflow/editor-core`'s insert and drop commands).
- In the editor, `@sciflow/editor-core`'s `CitationNodeView` gives the
  citation a `contentDOM`, so its text is editable in place, and a caret
  at the end of a paragraph that ends with a citation sits inside it.
  Typing there extends the citation. This is SciFlow's behaviour, the
  same before the PR, but the PR's numbered list turns the id into a
  wrong number.

## Proposed fix

In `exportBodyTextReferences()`, when the whole-marker rewrite does not
apply, still replace the citation's own reference ids inside its leading
"[…]" or "(…)", number by number, and leave every other number (pages,
years) alone:

- "[117, p. 5]" becomes "[4, p. 5]";
- "[114] More text 2020." becomes "[1] More text 2020.";
- a typed "(2021)" or "(2022)" stays, since neither is the citation's id.

The diff is `shared/playwright/checks/sync/ui-library-1053/fix3.diff`
(relative to the OJS root, one file, 28 lines added, 8 removed;
`updateLeadingReferenceIds()`). It keeps the developer's `custom` and
drop handling as they are. Tried 2026-11-11 at the round-3 heads with
`bin/try-fix.js` and `cite.js` (run `fix3`): "[4, p. 5]", "[1] More text
2020.", "(2021)" and "(2022)" kept, the merge "(2; 1)", "[2]", "[4]", the
PDF with 11 links, the deleted-reference refusal (U48 A27) unchanged. A
custom year that equals its own reference's id ("(2021)" citing id
2021) would still be rewritten. That case is rare, and it is the one
the developer's mode check was meant for.

The link around "More text 2020." is the editor's: the typed text is
inside the citation. Placing the caret after a paragraph-final citation
rather than inside it is SciFlow's to change. It is not part of this fix.
Round 2's `fix2.diff` (renumber only when the digits are exactly the
ids) is superseded: round 3 fixes its cases, and it leaves both cases
above as they are.

A unit test of `exportBodyTextReferences()` with "[id, p. 5]" (custom),
"[id] text" (not custom) and "(2021)" (custom) would cover it.

Small: one function in one ui-library file, plus a unit test.

Still as before, outside this finding: A27 (a citation to a deleted
reference stops every export) and A28 ("[2, 4] (Reference 2; Reference
4)") wait for the team's answer.

## Summary

The editor now writes the reference's number in the list into the
citation and renumbers it when the list changes. A citation to a
reference deleted on "References" has no number any more, and it keeps
the one it had. The references below it move up one, so a citation to
the next reference gets that same number:

- Beta (2) and Gamma (3) cited, Beta deleted: both citations read "[2]",
  one to the deleted Beta and one to Gamma.
- "Export to HTML" and "Preview: PDF" then refuse with "Unable to
  export references. Missing reference IDs: 14. …" (U48 A27). The text
  shows no "14" anywhere. Before this commit the editor showed the ids
  ("[14]", "[15]"), and the broken citation could be found by the
  number in the message.

## Impact

- **Lost**: nothing is published wrong, since the export refuses. The
  editor shows two different references under one number, and the
  refusal names a number the editor does not show. The only way to find
  the broken citation is to click each "[2]" and watch which reference
  the side panel highlights.
- **Who**: an OJS editor who deletes a cited reference that is not the
  last in the list, then exports the Body Text.
- **Way round**: click through the citations with the number in
  question; the one that highlights no reference is the broken one.

Low: the result is right in the end and nothing is lost. It would be
medium if the team answers A27 with "export it as text with a warning",
since the galley would then publish "[2]" for Beta beside a list where 2
is Gamma.

## Steps to reproduce

Preconditions: PKP's default dataset, OJS `main` with the three PRs'
round-4 heads checked out and built.

1. Sign in as `dbarnes`, open a submission in Production, and under the
   version's "References" add four references: "Alpha, A. (2020). First
   reference.", "Beta, B. (2021). Second reference.", "Gamma, G. (2022).
   Third reference.", "Delta, D. (2023). Fourth reference.".
2. Open "Body Text", type "P1 cites Beta: ." and drag Beta into it, then
   on a new line "P2 cites Gamma: ." and drag Gamma into it. The
   citations read "[2]" and "[3]". Press "Save".
3. Open "References" and delete Beta (the row's menu, "Delete", "OK").
4. Open "Body Text" again (or reload it).
5. "Export" › "Export to HTML".

**Expected**: Beta's citation no longer shows a number that belongs to
another reference (for example "[?]"), Gamma's reads "[2]", and the
refusal lets the editor find the citation it is about.

**Observed** (the drive's run `m1`, references Alpha 13, Beta 14, Gamma
15, Delta 16):

```
P1 cites Beta: [2].     (source 14, deleted)
P2 cites Gamma: [2].    (source 15)
side panel: 13, 15, 16
Export to HTML: "Unable to export references. Missing reference IDs: 14.
                 Citations with invalid or empty sources: 0."
```

## Cause

`src/components/BodyTextEditor/citationMarker.js`,
`citationMarkerReplacements()` returns no replacement for a token whose
reference has no number (`numbers.get(token.id)` is null), so the
editor's renumbering (`citationMarkerFeature.js`,
`citationMarkerTransaction()`, run on load and when the references
change) leaves the deleted reference's citation at its old number while
it renumbers the rest.

## Proposed fix

When the editor renumbers, give a token whose reference is no longer in
the list a placeholder instead of leaving its old number: an optional
`missing` argument to `citationMarkerReplacements()`, passed as `'?'`
from `citationMarkerTransaction()` only. The export does not pass it,
so a citation to an entry of the document's own bibliography keeps its
text there. The token keeps its reference id, so the number comes back
if the list holds the reference again.

The diff is `shared/playwright/checks/sync/ui-library-1053/fix4.diff`
(relative to the OJS root, two files, 16 lines added, 3 removed). Tried
2026-11-13 at the round-4 heads with `bin/try-fix.js` and `markers.js`
(run `fix4`): after the deletion, and again after a reload, the
citations read "[?]" (Beta) and "[2]" (Gamma); the export's refusal is
unchanged (A27).

The refusal's text (`publication.bodyText.error.unresolvedReferences`,
pkp-lib) could also say that such citations show as "[?]". That is a
wording choice for the developer and part of A27's answer.

A unit test of `citationMarkerReplacements()` with a token whose id is
missing from `numbers`, with and without `missing`, would cover it.

Small: two functions in ui-library, plus a unit test.

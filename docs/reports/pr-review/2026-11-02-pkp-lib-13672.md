## 2. A journal whose DOI settings still hold the author-response kind can no longer save the DOIs "Setup" tab (medium)

A journal could turn the author-response kind on only through the
settings API (the Setup form never offered the box: it was commented
out from its introduction, ojs `30e82d3876`). The PRs make OJS's
`schemas/context.json` refuse the kind (round 1's cleanup note), but a
value already stored stays, and the Setup form sends it back with
every save. The schema change is the PRs': at the base the API stored
the kind with a 200 (round 1's walk).

**Steps** (OJS, `main` at the PR heads, PKP's `main` dataset; the same on
`ore` at the `ore` heads, PKP's 3.5 dataset upgraded)

1. The journal's `enabledDoiTypes` holds `["publication","peerReview","authorResponse"]`
   (in the database here; before the PRs, `PUT api/v1/contexts/1` with
   that list).
2. dbarnes: Settings › Distribution › DOIs › "Setup", "Save" with
   nothing changed. Expected: "Saved". Observed: the request answers
   400 and the form shows "Please correct one error. Go to Items with
   DOIs: The selected enabledDoiTypes.2 is invalid." No field is marked.
3. Untick "Peer Review", "Save"; tick it again, "Save". Observed: 400
   each time ("enabledDoiTypes.1 is invalid"), because the form sends
   `enabledDoiTypes[]=authorResponse` with every save. The setting stays
   unchanged, so the prefix, the suffix pattern and the automatic
   assignment can't be changed either.

**Cause** ojs `classes/components/forms/context/DoiSetupSettingsForm.php:70`:
the `enabledDoiTypes` field takes the stored list as its value without
checking it against the options it offers. Nothing removes
`authorResponse` from a stored setting: `main` has no upgrade step for
it, and the `ore` migration run by hand drops only the column.

**Fix** Give the field only the kinds the form knows
(`array_values(array_intersect($context->getData(Context::SETTING_ENABLED_DOI_TYPES) ?? [], array_column($this->objectTypeOptions, 'value')))`),
so the next save drops the stale kind:
[fix-ojs-stored-kind.diff](../../../shared/playwright/checks/sync/pkp-lib-13672/fix-ojs-stored-kind.diff),
one line in the file both OJS PRs touch. Tried on both branches: the
three saves above answer 200, and the stored setting becomes
`["publication","peerReview"]`, then `["publication"]`, then
`["publication","peerReview"]`. Check:
[stored-kind.js](../../../shared/playwright/checks/sync/pkp-lib-13672/stored-kind.js).

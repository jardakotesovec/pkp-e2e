## Finding 1 — A book file address with letters in its version part shows a server error (fixed in round 2)

- **Severity** low · **Effort** small · **Kind** intention gap · **Crash** server
- **Affects** main: OMP · 3.5: OMP · 3.4: OMP (code) · 3.3: OMP (code); PostgreSQL only (code: MySQL casts the string)

### Impact

- **Lost.** Only the "404 Not Found" message. The visitor gets a blank
  page, and each request writes a fatal error to the server log.
- **Who.** Anyone who opens, mistypes or makes up such an address, mostly
  crawlers. No link the press offers leads to one.
- **Way round.** The book's page and its "Versions" list open every
  version's files.

Low: nothing is lost but the not-found message, and no link of the
press's leads there.

### Steps to reproduce

Preconditions: PKP's default test dataset for `main`, OMP on PostgreSQL.
Book 5, "Bomb Canada and Other Unkind Remarks in the American Media", is
published in one version (id 5), with an available format (id 2) whose
file is 41.

Signed out:

1. Open `/index.php/publicknowledge/en/catalog/view/5/version/5/2/41`.
   The file's view page opens (control).
2. Change `version/5` to `version/image.gif`.
3. Change it to `version/5abc`.
4. Repeat steps 1 to 3 with `catalog/download` in place of `catalog/view`.

**Expected.** Steps 2, 3 and their download twins show "404 Not Found",
as `version/14` (another book's version) already does.

**Observed.** Each answers a blank page, status 500:

```
PHP Fatal error:  Uncaught PDOException: SQLSTATE[22P02]: Invalid text representation: 7 ERROR:  invalid input syntax for type bigint: "image.gif"
PHP Fatal error:  Uncaught PDOException: SQLSTATE[22P02]: Invalid text representation: 7 ERROR:  invalid input syntax for type bigint: "5abc"
```

### Cause

`CatalogBookHandler::download()` (also behind `view()`) takes the version
part as it comes (`$publicationId = array_shift($args);`) and hands it to
`PublicationFormatDAO::getByBestId($representationId, $publicationId)`,
whose query binds it against `pf.publication_id`, a `bigint`. PostgreSQL
refuses the text and the exception is not caught.

`pkp/omp#2530` adds the digits-only check to `book()` only. `download()`
is the only other route in the three apps that reads a `version/{x}`
segment (code: a grep for `'version'` in `pages/` and `plugins/` of each
app, `lib/pkp` included). The OJS and OPS handlers read it once, in
`initialize()`, which the PRs cover.

Reach:

- `catalog/view` and `catalog/download`, signed in or not (on screen,
  signed out).
- A numeric id of another book answers 404 already: the format lookup
  succeeds or not, and the loop over the book's publications finds no
  match (on screen).

### Proposed fix

The same check `pkp/omp#2530` puts in `book()`
([fix-omp-download.diff](https://github.com/jardakotesovec/pkp-e2e/blob/main/shared/playwright/checks/sync/pkp-lib-13657/fix-omp-download.diff)):

```diff
         if ($subPath === 'version') {
-            $publicationId = array_shift($args);
+            $publicationId = (string) array_shift($args);
+            if (!ctype_digit($publicationId)) {
+                throw new NotFoundHttpException();
+            }
+            $publicationId = (int) $publicationId;
             $representationId = array_shift($args);
```

Tried on OMP `main` at the PR head: steps 2 to 4 answered 404 with an
empty server log; step 1, its download twin, `version/14` and the book
page's addresses answered as before.

- **What goes with it.** It fits in `pkp/omp#2530` as a second hunk, and
  in the 3.5 port of Finding 2.

Small: five lines in one method.

## Finding 2 — OMP 3.5 keeps the book page's server error; the PRs have no 3.5 port for OMP (fixed in round 2)

- **Severity** low · **Effort** small · **Kind** intention gap · **Crash** server
- **Affects** 3.5: OMP (main is fixed by `pkp/omp#2530`; 3.4 and 3.3 none, code, as U69 A3 says)

### Impact

As U69 A3 ([pkp-e2e#285](https://github.com/jardakotesovec/pkp-e2e/issues/285)):

- **Lost.** Only the "404 Not Found" message.
- **Who.** Anyone opening a book's version address with a wrong id, on
  an OMP 3.5 install. 3.5 is released, so installs carry it now.
- **Way round.** The book's own address and its "Versions" list.

Low, as A3.

### Steps to reproduce

On OMP `stable-3_5_0` with the 3.5 test dataset, signed out, open
`/index.php/publicknowledge/en/catalog/book/5/version/image.gif`, then
`…/version/14`, `…/version/1018` and `…/version/` (empty).

**Expected.** "404 Not Found" each time.

**Observed.** A blank page, status 500, each time:

```
PHP Fatal error:  Uncaught Error: Typed property APP\pages\catalog\CatalogBookHandler::$publication must not be accessed before initialization in pages/catalog/CatalogBookHandler.php:120
```

`…/version/5abc.gif` opens version 5.

### Cause

OMP `stable-3_5_0` declares `public Publication $publication;` (since
`pkp/omp#1907`), as main did before `pkp/omp#2530`. The issue's note
that 3.5 already answers 404 was read on OJS, whose 3.5 property is
untyped. OJS and OPS 3.5 do answer 404 here (on screen); they keep only
the `(int)` cast, so `version/1abc.gif` opens version 1 there.

### Proposed fix

A `stable-3_5_0` port of `pkp/omp#2530`, with Finding 1's hunk
([fix-omp-3_5.diff](https://github.com/jardakotesovec/pkp-e2e/blob/main/shared/playwright/checks/sync/pkp-lib-13657/fix-omp-3_5.diff)).
`pkp/omp#2530`'s diff applies to the 3.5 file with offsets only.

Tried on OMP `stable-3_5_0` (`19d3418a2`): every bad address of both
findings answered 404 with an empty server log; the book page, its own
version, its file view and download, and the manager's view answered
as before.

- **Alternatives.** OJS and OPS 3.5 ports of the digits-only check,
  which would close the `(int)` cast there; they answer 404 already, so
  they are optional.

Small: the PR's diff, ported.

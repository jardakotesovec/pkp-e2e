## 1. On `main`, #284 changes nothing: the theme never runs the code it adds to (medium)

**Steps** (OJS `main`, the theme at #284's head, ALTCHA on)

1. Journal home, menu "Login", sign in through the modal.
   Expected: signed in. Observed: the page reloads and the visitor is
   still anonymous, with no message. The modal's form has
   `action=""`, so it posts to the page it is on.

**Cause** `HealthSciencesThemePlugin.inc.php:118`:
`HookRegistry::add('TemplateManager::display', …)`. `main` has no
`HookRegistry` class, so `init()` fails ("Plugin
HealthSciencesThemePlugin failed to handle the hook
PluginRegistry::categoryLoaded::themes", `Class "HookRegistry" not
found`). `loadTemplateData()` never runs, so neither `loginUrl` nor the
PR's ALTCHA assignment reaches the template. This is older than the PR:
the theme's port to `main` that the PR's thread mentions.

**Fix** `use PKP\plugins\Hook;` and `Hook::add(...)`. Tried: with that
one change, #284's head signs in from the modal on the home page and on
a static page, with the `altcha` field posted (`HS_PHASE=head-hookfix`).
It can go in #284 or in the planned `main` port. #284 cannot be seen
working until one of them lands.

## 2. With ALTCHA off for Register or lost password, those forms now run the check anyway (low)

**Steps** (OJS 3.5 at #283's head; `altcha = on`, `altcha_on_login = on`,
`altcha_on_register = off`, `altcha_on_lost_password = off`)

1. Open Register, then "Forgot your password?".
   Expected: no ALTCHA on either form, as at the base. Observed: each
   form holds an `<altcha-widget>`, and Register posts an `altcha`
   field. The server does not check it, and the account is created.

**Cause** `HealthSciencesThemePlugin.inc.php` `assignLoginModalAltcha()`
calls `FormValidatorAltcha::insertFormChallenge()` on every anonymous
page. That function sets the shared `altchaEnabled` and
`altchaChallenge` variables, which `userRegister.tpl` and
`userLostPassword.tpl` read for their own forms. It runs at
`TemplateManager::display`, after the page handler decided.

**Fix** Give the modal its own variables: save the page's
`altchaEnabled`/`altchaChallenge`, call `insertFormChallenge()`, copy
the result to `loginModalAltcha…` names, put the page's values back, and
have `loginForm.tpl` read the modal names when
`$formType === "loginModal"`. Not tried.

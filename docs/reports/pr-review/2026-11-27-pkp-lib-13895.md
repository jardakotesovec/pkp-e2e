Nothing is outstanding. `FilterHelper::installFilterGroups()` now
updates an installed group's display name, description, input type and
output type from the plugin's `filterConfig.xml` when one of them
differs, and writes nothing when none does. The three pkp-lib PRs are
the same change.

The change runs from `Plugin::installFilters()` on every installer's
`postInstall` (a fresh install, `tools/upgrade.php`, a gallery plugin
upgrade that runs the installer) and from
`lib/pkp/tools/installPluginVersion.php`. On every branch each filter
group's symbolic is declared in one `filterConfig.xml` only, with all
five attributes, so no two files take turns at a row. Every
migration that writes `filter_groups` (OJS/OPS `I7796` and `I10659`
for Crossref, OJS `I11593` for DOAJ, OMP `I10561` for ONIX, the
namespace migrations) writes the value its plugin's `filterConfig.xml`
already holds, so the update after the migrations never undoes one.

**Steps** (kept walk
`shared/playwright/checks/sync/pkp-lib-13895/walk.sh <line> <app> <pr> <older dataset> <symbolics> <plugin|->`,
on dataset fleet 1, PKP's test dataset, at the PR base and at the head
checked out in the app's `lib/pkp`; OJS, OMP and OPS on `main` (from
the 3.3 dataset), 3.5 (from the 3.4 dataset) and 3.4 (from the 3.3
dataset, PHP 8.2)):

1. Load the older dataset, so the app's upgrade runs, and compare
   `filter_groups` with every `filterConfig.xml`.
   Base and head alike: every row equals its file, and the two tables
   are identical.
2. Set the Crossref, DataCite or ONIX groups' display name, description
   and output type to other values (a schema the file no longer names),
   then run `php tools/upgrade.php upgrade`.
   Base: the rows stay as set. Head: each altered row is updated once
   (a trigger counts the `UPDATE`s) and equals its file again.
3. Run the upgrade again. Head: no row is written.
4. Alter one plugin's groups and run
   `php lib/pkp/tools/installPluginVersion.php <plugin>/version.xml`
   (OJS DataCite on `main`, Crossref on 3.5, PubMed on 3.4; OMP ONIX).
   Head: that plugin's groups are updated and equal the file. OPS has
   no bundled plugin with filters that the tool can load (Crossref's
   `version.xml` names no class), so the step is not run there.

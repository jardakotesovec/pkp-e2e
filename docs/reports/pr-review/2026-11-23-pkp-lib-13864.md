## 3. With ORCID off, switching a person who has an ORCID iD to another type is a server error (medium)

**Steps** (OJS, a fresh install)

1. A journal with ORCID enabled; a submission's contributor "Ida
   Offorcid", Person, carries a verified ORCID iD.
2. Settings › Users & Roles › ORCID: "Enable ORCID functionality"
   off.
3. Workflow › Publication › Contributors › Ida Offorcid › "Edit":
   choose "Organization or group", fill "Organization Name", "Save".
   Expected: saved, the iD and its tokens removed. Observed: "An
   unexpected error has occurred. Please reload the page and try
   again."; nothing is saved and the iD stays. `PUT …/contributors/{id}`
   answers 500 `{"error":"Call to a member function collect() on array"}`.

**Cause** `api/v1/submissions/PKPSubmissionController.php:1970` sets the
author's affiliations to a plain array; the new block at line 1990 then
calls `OrcidManager::removeOrcidAccessToken()`, which builds a
`RevokeOrcidToken` job whose constructor calls `->collect()` on the
affiliations (`jobs/orcid/RevokeOrcidToken.php:38`).

**Fix** Move the new block above the affiliations loop (after
`Repo::author()->validate()`), so the job is built from the author's
own collections; or have the job's constructor accept an array
(`collect($identity->getData('affiliations'))`). Tried: the move
([trial-fix-r2.diff](../../../shared/playwright/checks/sync/pkp-lib-13624/trial-fix-r2.diff)):
the form and the API switch save, the stored iD and its tokens are
gone, no error in the log; with ORCID on the switch is still refused.

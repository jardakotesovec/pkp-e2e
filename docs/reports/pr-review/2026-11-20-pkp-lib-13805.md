## 1. A title with italics or a prefix prints HTML code in the PDF (medium)

**Steps** (OJS, PKP's default dataset)

1. Submission 9: give the version the title `<i>Reason</i> Reclaimed`
   (what the title field stores for "Reason" in italics; sent here
   through `PUT …/publications/10`; the workflow header shows it in
   italics). Its "Body Text": type a
   line, "Save", then "Export" › "Preview: PDF", then "Create PDF".
   Expected: the title in the PDF's header as the workflow header shows
   it, "Reason" in italics. Observed: `<i>Reason</i> Reclaimed`, in
   the preview and in the stored PDF's text.
2. Same submission, prefix "L'". Expected: "L' Hansen & Pinto: Reason
   Reclaimed". Observed: `L&#039; Hansen & Pinto: Reason Reclaimed`.

**Cause** `src/pages/workflow/components/publication/WorkflowPublicationBodyTextPDFMetadata.js:56`:
`renderTitle()` escapes `publication.fullTitle` with `escapeHTML()`, but
the API's `fullTitle` is already HTML (`getFullTitles('html')`: inline
tags kept, the prefix passed through `htmlspecialchars`), so it is
escaped twice.

**Fix** Insert the title unescaped; `preparePDFHTML()` runs DOMPurify
over the whole document in both the preview and the PDF, as it already
does for the abstract. Tried (`title-fix.diff`): "*Reason* Reclaimed"
in italics in the preview and "Reason Reclaimed" in the PDF's text;
"Hansen & Pinto" unchanged. The prefix was not driven with the fix;
its `&#039;` is an entity that the unescaped title decodes.

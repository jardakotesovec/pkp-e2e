## 3. A label missing in the article's language prints as a key (question)

**Steps** (OJS, PKP's default test dataset, as `dbarnes`)

1. Switch submission 15 to French (fr_CA), give it pages, and open
   Publication › Body Text › Export › Preview: PDF.
   Observed: "Journal de la connaissance du public, Vol. 2(1),
   ##issue.pagesAbbreviated## 5–8, 2015"; "Create PDF" builds the stored
   PDF from the same header.
   An anonymous contributor would print
   "##submission.submit.contributorType.anonymous##".

**Cause** `api/v1/bodyText/PKPBodyTextController.php:161`:
`__($key, locale: $locale)` returns `##key##` for a key the locale
lacks; both keys are new in this release and exist in `en` only
until Weblate fills them in.

**Choices** (a) leave it to the translations, as for screen text; (b)
fall back to the journal's primary language, then English, for a
missing label, as the metadata now does. The review leans to (b): the
PDF is a stored galley, which a later translation does not repair.

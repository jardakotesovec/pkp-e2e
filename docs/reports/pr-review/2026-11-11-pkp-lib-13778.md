**Rounds.** Round 1 (2026-11-11) found that the repair left the bare
`##default.submission.step…##` help texts and checklist sentence of a

(`getMissingKeyValue()`) and narrowed the source locales to `en` and
the config's default. Round 3 (2026-11-26, the heads rebased; the

## Summary

On both lines, an upgrade at the round-3 heads now gives the Editorial
Board Member group its French name and abbreviation ("Membre du comité
éditorial", "MCE") and OMP's migrated highlights the French link text
("Lire plus"), from 3.3 and 3.4 alike. On a database already upgraded
at the base, the repair fixes the group in every case: the missing
French name, and the bare key a French-primary context got.

The highlight link text is repaired only when it is the bare key
`##common.readMore##`. At the base, `I9262_Highlights` sets each link
text after `Locale::setLocale('fr_FR')`, an invalid code then, which
restores the primary locale. Only when that locale has no translations
(config `locale = en_US`, kept from 3.3) is the text the bare key. With
`locale = en`, as every 3.4 config says and any 3.3 site that updated
it, the French link text is the English "Read More", and the repair
leaves it. So the repair misses most of the presses it is written for.

## Impact

- **Lost**: nothing; on the press's home page, the button of each
  highlight that was a spotlight before the upgrade reads "Read More"
  in the French interface.
- **Who**: OMP presses that had spotlights, upgraded to 3.5.0-0…6 from
  3.3 or 3.4 with a config saying `locale = en`, and one of the 11
  renamed locales (`fr_FR`, `pt_PT`, `zh_CN`, `ja_JP`, `nb`, `bs`, the
  `sr`, `uz` and `be` variants) among a press's languages.
- **Way round**: the manager edits each highlight's link text in that
  language (Website → Highlights).

Low: an English label on one button, and every task still gets done.

## Steps to reproduce

1. Take PKP's 3.4 OMP dataset (`stable-3_4_0`, `[i18n] locale = en`)
   with every `fr_CA` replaced by `fr_FR`, and a spotlight on series 1
   (`plant.sh` in Evidence).
2. Upgrade it with `stable-3_5_0` at the PR base (`php tools/upgrade.php upgrade`).
3. Run `I13778_RepairRenamedLocaleDefaults` from the PR head on that
   database, as the 3.5.0.0–3.5.0.99 upgrade block will when the
   release is bumped (`repair-driver.php` in Evidence).
4. Open the press's home page in French: the highlight's button reads
   "Read More" (`highlight_settings`, `urlText`, locale `fr`).

**Expected**: "Lire plus", as the same steps give from a 3.3 dataset
whose config still says `locale = en_US`, and as a fresh upgrade at the
PR head gives from either.

## Cause

`I13778_RepairRenamedLocaleDefaults::repairHighlightUrlTexts()` updates
only rows whose value equals `getMissingKeyValue('common.readMore')`.
The help texts' repair uses `isBrokenDefault()`, which also accepts the
source locales' default text; the link text's does not.

## Proposed fix

Treat the link text as the help texts are treated: broken when it is
the bare key or `common.readMore` in `en` or the config's default
locale. Tried on both lines and all three apps (Evidence): every French
link text becomes "Lire plus", a press's own link texts ("Découvrir",
"Read more here") stay, and a second run changes nothing.

```diff
--- a/classes/migration/upgrade/v3_5_0/I13778_RepairRenamedLocaleDefaults.php
+++ b/classes/migration/upgrade/v3_5_0/I13778_RepairRenamedLocaleDefaults.php
@@ up()
             $this->repairEditorialBoardMemberGroups($locales);
-            $this->repairHighlightUrlTexts($locales);
+            $this->repairHighlightUrlTexts($locales, $sourceLocales);
@@ repairHighlightUrlTexts()
      * Translate the link texts of the highlights migrated from the OMP spotlights by I9262_Highlights,
-     * that were set to the bare locale key.
+     * that were set to the bare locale key or to the configured default locale's text.
      */
-    protected function repairHighlightUrlTexts(array $locales): void
+    protected function repairHighlightUrlTexts(array $locales, array $sourceLocales): void
     {
         foreach ($locales as $locale) {
             $urlText = __(self::HIGHLIGHT_URL_TEXT, [], $locale);
             if ($urlText === '') {
                 continue;
             }
             DB::table('highlight_settings')
                 ->where('setting_name', 'urlText')
                 ->where('locale', $locale)
-                ->where('setting_value', $this->getMissingKeyValue(self::HIGHLIGHT_URL_TEXT))
-                ->update(['setting_value' => $urlText]);
+                ->get()
+                ->filter(fn ($row) => $this->isBrokenDefault((string) $row->setting_value, self::HIGHLIGHT_URL_TEXT, $sourceLocales))
+                ->each(fn ($row) => DB::table('highlight_settings')
+                    ->where('highlight_id', $row->highlight_id)
+                    ->where('locale', $locale)
+                    ->where('setting_name', 'urlText')
+                    ->update(['setting_value' => $urlText]));
         }
     }
```

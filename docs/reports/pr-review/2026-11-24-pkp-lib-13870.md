## 1. An image file the browser cannot preview reads "Failed to load the image. The file may be corrupted." for as long as it uploads (low)

The regenerated lockfile takes `dropzone` (the library under
`dropzone-vue3`) from `6.0.0-beta.2` to `6.3.5`. Dropzone 6.3.5 sends
its `error` event when it cannot draw a thumbnail for a file of an
`image/*` type; 6.0.0-beta.2 did not. The uploaders pass that event on
as an upload error until the upload answers.

**Steps** (OJS, a fresh install; OMP and OPS share the components)

1. As `author.alex`, start a submission and, on "Upload Files", add a
   TIFF figure (any valid `.tif`; Chrome draws none) on a slow
   connection (the check holds the upload at 48 bytes/s).
   Expected: the row shows the name and "Cancel upload" until the upload
   is done (the base). Observed: a red "Failed to load the image. The
   file may be corrupted." under the name until the upload is done; the
   file is then stored normally and the message goes.
2. As a journal manager, add an announcement and put the same TIFF (or a
   text file named `.png`) in "Image".
   Expected: the name and "Cancel upload" (the base). Observed: the same
   red message under "Image" while the upload runs.

On a fast connection nothing shows, but the hidden preview keeps the
`dz-error` class, which the suite's announcement test reads.

**Cause** `node_modules/dropzone/dist/dropzone.js:1116` (6.3.5):
`_processThumbnailQueue` emits `error` with `dictThumbnailError` when
`createThumbnail` fails; `FileUploader.vue:163` (`dropzoneError`) and
`FieldUpload.vue:356` (`onError`, which `FieldUploadImage` inherits) add
that message to the file's or the field's errors. `FileUploader`'s
preview template is `<p></p>`, so it never shows the thumbnail it asks
for.

**Fix** Keep `dropzone` at the version the apps ship today: in
ui-library,
`npm install dropzone@6.0.0-beta.2 --save-exact --package-lock-only --workspaces=false`,
then `npm run sync-lock` in each app (the README's own steps). Tried on OJS at the PR head: the slow
uploads show no message in either box, and the announcement test passes
again. Diff: `shared/playwright/checks/sync/pkp-lib-13870/dropzone-pin.diff`.
To take 6.3.5 instead: `createImageThumbnails: false` in `FileUploader`
(it shows no thumbnail), and skip `dictThumbnailError` in the other
uploaders' error handlers (`FieldUpload`'s `onError`,
`useFileMediaUploader`'s `onUploadError`). Not tried.
Check: `shared/playwright/checks/sync/pkp-lib-13870/thumbnail-error.js`
(`THROTTLE=48` for the slow case).

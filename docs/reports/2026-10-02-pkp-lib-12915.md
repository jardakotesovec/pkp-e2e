Round 3 replaces round 2's bootstrap preload with the usual per-site line
(`$junk = \APP\publication\Publication::STATUS_PUBLISHED;`) in `DatabaseEngine::buildQuery()` and
`PKPStatsEditorialQueryBuilder::_getBaseQuery()`. That fixes the two sites round 1 found: the category
page and the editorial statistics answer 200. Two more OMP requests read a `PKPPublication` constant
before any publication is loaded, and they still answer 500 with the same fatal once the PHP process
has served the catalog or a book page:

1. Statistics › Monographs: the "Files", "Countries", "Regions" and "Cities" reports with a search
   phrase.
2. `PUT /api/v1/dois/submissions/deposit`.

Each needs one more line of the same kind. Everything else in round 3 holds:

- The three round-2 gaps are fixed: the DataCite name, the CLI refusing an empty name, and ONIX
  `PublisherName`. ONIX's new warning cannot be seen anywhere (below).
- The three suites are green on CI at the round-3 heads.

## Impact

- **Lost**: the four monograph statistics reports filtered by a search phrase, and a DOI deposit made

- **Who**: OMP press managers; on PHP 8.3 with OPcache, once the same PHP process has served the press

Medium:

## Steps to reproduce

Preconditions: OMP at the PR heads, PHP 8.3 with OPcache, served by one PHP process (`php -S`). A press
with DOIs enabled, a category "arts" and one published book with a PDF format. Start or restart the
server after the press exists.

1. Open the press's catalog (`/index.php/<press>/catalog`), then a book page
   (`/index.php/<press>/catalog/book/<id>`).
2. As the press manager, open Statistics › Monographs, type "Order" in the search box and download the
   "Files" report: `GET /index.php/<press>/api/v1/stats/publications/files?dateStart=2025-01-01&dateEnd=2026-09-30&searchPhrase=Order`.
3. `PUT /index.php/<press>/api/v1/dois/submissions/deposit` with `{"ids":[<id>]}`.

**Expected.** 200, as the category page and `stats/editorial` now give in the same order.

**Observed.** 500 for step 2 (and for `countries`, `regions`, `cities`) and for step 3. The server log:

```
PHP Fatal error:  During inheritance of PKP\publication\DAO, while autoloading
APP\publication\Publication: Uncaught Error: Class "PKP\publication\PKPPublication" not found in
classes/publication/Publication.php:28
```

## Cause

Round 1's mechanism. omp#2372 gives `APP\publication\Publication` a trait, so OPcache declares it at
run time. A request whose first reference to a publication class is a `PKPPublication::` constant
then fails, once an earlier request in the same process loaded the APP class first. The two requests
above reach such a constant unguarded:

- `PKPStatsPublicationController.php:827`, in `_processSearchPhrase()`, called from
  `validateParams()` (line 729). The guards at 181 and 260 cover `getMany()` and `getManyTimeline()`
  only, and the page always sends `dateStart`, which skips the earlier publication load.
- `PKPDoiController.php:531`, in `depositSubmissions()`. The guards are in
  `markSubmissionsRegistered()` (575) and `markSubmissionsStale()` (679).

OJS and OPS never reach `PKPPublication` first: their DOI plugins (DataCite or DOAJ on OJS, Crossref on
OPS) load `APP\publication\DAO` in every request (206 of 206 OJS requests, 174 of 174 OPS requests
traced).

## Proposed fix

- The same line at the top of `PKPStatsPublicationController::_processSearchPhrase()` and
  `PKPDoiController::depositSubmissions()`. Not tried.
- Also `OpenSearchEngine` (line 276, the category page and search with the OpenSearch driver), which
  reads the constant the same way. Not driven: needs that driver.
- Alternative: round 2's two `class_exists()` preloads in `lib/pkp/includes/bootstrap.php`. Tried in
  round 2: with them every site above answered 200, and it covers sites not yet found.

## Further findings

- **ONIX warning not visible (low · small).** For a book stamped without a publisher, ONIX now gives
  the stamped press name as `PublisherName` (`<onix:PublisherName>Stamped Press C</onix:PublisherName>`,
  fixed). The new warning `plugins.importexport.onix30.export.warning.publisherNotStamped` reaches no
  screen, for three reasons:
  - The Native XML export runs the ONIX filter with a throw-away deployment
    (`PublicationFormatNativeXmlFilter.php:62`), so its result reads only "The export completed
    successfully.".
  - The ONIX 3.0 tool's own export fails before the filter runs (known, U74).
  - There is no command-line export.

  The warning can stay for when the ONIX export works; it does nothing today.

## What held

  answer 500, so the lines are what fixes them.
- **The other guarded sites:** `PKPDoiController` 575, 679, `PKPStatsPublicationController` 181, 260,

  identity needs a name: …" on OJS, OMP and OPS, and changes nothing.
- **Everything round 2 listed as held.**

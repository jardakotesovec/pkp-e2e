The second review of the pkp-lib#7527 PR set, against the heads pushed on 2026-10-02 and the
"Implementation decisions" comment as rewritten the same day. It replaces the first report
(2026-10-01).

## Summary

Every finding of the first review is fixed at the new heads: OMP's category pages and editorial
statistics no longer fail, a major version with a new DOI takes the current identity, a field stamped
empty stays empty in every output, and OMP's `DC.Source` shows the stamped name. On CI the OMP suite
is now green. Three small gaps against the decisions remain:

1. an unstamped article in a stamped issue gets the issue's old journal name in its DataCite deposit;
2. the CLI tool can clear the name, which silently turns a stamped record back into an unstamped one;
3. OMP's ONIX export puts the press's current publisher into a book stamped without one.

None breaks a screen or a test, and the three suites are green at the PR heads on CI. On the suite side the decided rule that a place is recorded at
publication changes what the "How to Cite" settings do to articles already published; the companion
branch follows it.

## Impact

- **Lost**: correct journal identity in three narrow places: one DataCite deposit case, ONIX for books
  stamped without a publisher, and records an operator "corrects" by clearing the name.
- **Who**: journals depositing to DataCite that import articles into existing issues; presses
  exporting ONIX that had no publisher when they published; operators of the CLI tool.
- **Way round**: re-stamp with the CLI tool (1, 3); do not clear the name (2).

Low: each needs an uncommon combination, and none loses data.

## Steps to reproduce

### 1. OJS: DataCite article deposit takes the issue's old name (low · small)

1. In a journal with DataCite, publish an issue (it is stamped with the journal's name, e.g. "Old Data
   Journal").
2. Rename the journal ("New Data Journal") and give it an online ISSN (`2049-3630`).
3. Import into that existing issue a native XML article without identity elements. As decided, it
   stays unstamped: its page shows `<meta name="DC.Source" content="New Data Journal"/>`.
4. Export the article's DataCite XML.

**Expected** (decisions, "Back-issues": unstamped content "uses the journal's current identity";
"Article vs. issue stamps": article deposits read the publication's stamp): `New Data Journal` with
the live ISSN, as the article's other outputs print.

**Observed**: `<publisher>Old Data Journal</publisher>` and `<titles><title>Old Data Journal</title>`
beside `<relatedItemIdentifier relatedItemIdentifierType="EISSN">2049-3630</relatedItemIdentifier>`:
the issue's old name with the journal's current ISSN.

### 2. OJS, OMP, OPS: clearing the name with the CLI tool unstamps the record (low · small)

1. Publish an article (or book, preprint), then rename the journal and give it an online ISSN.
2. `php tools/stampIdentityMetadata.php <context> publication_id <id> --name-en= --publisher='Given
   Publisher' --online-issn= --print-issn=0378-5955`, answer `y`.

**Expected** (decisions: "An empty value clears a field (except `--primary-locale`)", and a stamped
identity is "final ... including fields stamped empty"): the outputs carry "Given Publisher" and
`0378-5955`, and no online ISSN.

**Observed**: the tool warns "There is no name in the primary locale en." and reports "Publications:
1 stamped, 0 unchanged."; the stored rows are `printIssn 0378-5955` and `publisher Given Publisher`,
with no `contextName`. Every output then reads the journal's current values: the page shows
`citation_issn` `2049-3630` and "New Name Journal", OAI `<dc:publisher xml:lang="en">New
Publisher</dc:publisher>` and `<dc:source>2049-3630</dc:source>`. The same on OMP (OAI "New
Publisher", the citation "Toronto: New Name", ONIX `New Publisher` / `Toronto` beside the file's own
`<publisher>Hist Pub</publisher>`) and OPS (the citation's place the plugin's current "Victoria").

### 3. OMP: ONIX joins the current publisher to an old stamped identity (low · small)

1. A press with no publisher and no location publishes a book (stamped name "Second Old", initials
   "SOLD").
2. The press then sets the publisher "Later Publisher", the location "Later City" and a publisher code.
3. Export the book (Tools › Native XML, which carries the ONIX product, or the ONIX plugin).

**Expected** (decisions: a stamped identity is final, including fields stamped empty; no ONIX
exception is stated): no publisher from after the publication.

**Observed**: `<onix:PublisherName>Later Publisher</onix:PublisherName>` and no `CityOfPublication`,
while the same book's OAI record gives `<dc:publisher xml:lang="en">Second Old</dc:publisher>`.

## Cause

1. ojs `plugins/generic/datacite/filter/DataciteXmlFilter.php` line 174:
   `($publication?->getData('contextName') ?: $issue?->getData('contextName')) ?: $context->getName(null)`
   falls back to the issue's stamp for an article deposit, while the ISSN of the same deposit comes from
   `$publication->getOnlineIssn($context)`, which for an unstamped publication is the live value.
2. lib/pkp `classes/publication/HasContextIdentityMetadata.php` lines 34-37: `hasContextIdentity()`
   is decided by a non-blank `contextName` alone, and every resolver returns live values when it is
   false. `StampIdentityMetadataTool::parseOptions()` refuses an empty `--primary-locale` but lets
   every `--name-<locale>` be cleared, and `getPreviewWarnings()` (line 412) only warns.
3. omp `plugins/importexport/onix30/filter/MonographONIX30XmlFilter.php` lines 567 and 865:
   `$publication->getPublisher($context) ?: (string) $context->getData('publisher')`. ONIX requires a
   PublisherName, so some value is needed; the code comment gives the reason, the decisions do not.

## Proposed fix

1. Read the article deposit's name through the publication's resolver
   (`$publication->getPrimaryContextName($context)`), as the other article outputs do; keep the issue's
   stamp for issue deposits only. Not tried.
2. In the CLI tool, refuse a run that would leave no name in any locale ("A stamp needs a name"), the
   way `--primary-locale=` is refused. Not tried. Alternative: key `hasContextIdentity()` on
   `contextPrimaryLocale`, which a stamp always has.
3. For a stamped book without a publisher, use the stamped press name (as OAI's `dc:publisher` does),
   or state the ONIX exception in the decisions. Not tried.

## Further notes

- **"How to Cite" settings and published articles (a release-note point, no change asked).** Since the
  place is recorded at publication (OJS and OPS from the CSL plugin's "Publisher Location"), a place
  typed into the plugin's settings afterwards reaches only articles published later; articles already
  published, including those the upgrade migration stamped while the box was empty, keep no place.
  The settings window does not say so. #13430 moves the setting to the Masthead; until then the
  release notes could say it. The suite's U13 S6 asserted the old behaviour and now follows the new
  one on the companion branch.
- **OPS `PUT {"publisher": …}`** still answers 200 and drops the value; the checklist now states it.
- **Bootstrap preload**: every `tools/*.php` and `lib/pkp/tools/*.php` of the three apps, the
  installer and `php tools/upgrade.php check` still start.
- The CSL download of an OJS article published without an issue answers 500 to a signed-out reader;
  that is the existing pkp-e2e issue report U13 OJS1, not this PR set.

## What held

Re-walked on OJS, OMP and OPS at the new heads: the publish stamp; minor versions keeping, and major
versions with a new DOI taking, the current identity, also inside a published issue; an article
published later into a stamped issue taking the current identity while the issue and its issue-level
Crossref deposit keep the old one; Native XML import inheriting only from an issue in the same file
(an article imported into an existing issue, or an issue matched by `issue_identification`, stays
unstamped; an `<issues>` file gives each article its issue's identity); a field stamped empty staying
empty in OAI DC and MARC, the DC and Google Scholar tags, Crossref, DOAJ, PubMed and DataCite; OMP's
`DC.Source`; the CSL place rules as decided, including OMP's known gap; the CLI's `publication_id`,
`submission_id` (all versions), `issue_id` (with later versions), `year` and `all`, the refused
`--primary-locale=`, and re-runs reporting "unchanged".

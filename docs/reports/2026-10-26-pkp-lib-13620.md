## Summary

The PRs for `pkp/pkp-lib#13593` add two columns, `date_confirmed` and
`date_reverted`, for the step where an editor confirms an author's
response to reviews. A fresh install of any app gets them. An upgrade adds
them only on OJS, because only OJS has a PR adding the step to its
`upgrade.xml`. PKP's 3.5 test press and test server upgrade to 3.6 at the
PR heads without errors, but without the columns. On the upgraded press,
confirming a response through the review API answers 500 (`column
"date_confirmed" … does not exist`).

Round 1 (pkp-lib `d7c6c3bc06`) also broke the OJS upgrade: a doubled class
prefix in `upgrade.xml`, and a file name that did not match its class.
Round 2 (`b0145df8f5`, ojs `8f9fa9cf92`) fixed both. The OJS 3.5 test
journal now upgrades with both columns. Round 2 also fixed round 1's
minor PHP warning, logged on every change of editor.

Everything else the PRs add works as the issue asks, at the round-2
heads (walked on the default dataset; Evidence):

- reading one response;
- confirming and reverting it, and who may do so;
- the new no-op answers (a repeated confirm or revert changes nothing)
  and the 422 for reverting a response that is not confirmed;
- the public record listing a response only once it is public and
  confirmed.

## Impact

- **Lost**: on an upgraded press, confirming an author response through
  the review API (a 500). On an upgraded press or server, a schema that
  differs from a fresh install's, so any later code that reads the two
  columns fails there.
- **Who**: OMP and OPS sites upgrading to 3.6. No OMP or OPS screen offers
  author responses today (U30 OMP1). OPS has no review API.
- **Way round**: none in the app. An administrator can add the two
  columns by hand.

Low: no screen reaches it today. It would be medium once OMP shows author
responses or calls the confirmation, as pkp/pkp-lib#13524's screen will
on OJS.

## Steps to reproduce

Preconditions: PKP's default test dataset for `stable-3_5_0` (3.5.0.5),
loaded into OMP and OPS `main` with `lib/pkp` at the pkp-lib PR head.

1. In each app, run `php tools/upgrade.php upgrade`. It ends with
   "Successfully upgraded to version 3.6.0.0".
2. `review_round_author_responses` has `response_id, review_round_id,
   user_id, created_at, updated_at, doi_id`, with no `date_confirmed`
   and no `date_reverted`.
3. OMP: as `dbarnes`, for a response of review round 1 of book 1,
   `PUT {press}/api/v1/reviews/1/1/authorResponse/{id}/confirmation`
   with `{"markAs":"confirmed"}`. The answer is 500, `SQLSTATE[42703]:
   Undefined column … "date_confirmed"`. The `GET` of the same response
   answers 200.

## Cause

`lib/pkp/classes/migration/upgrade/v3_6_0/I13593_AddDateConfirmedAndDateRevertedToReviewRoundAuthorResponses.php`
adds the columns, and each app's `dbscripts/xml/upgrade.xml` decides
which pkp-lib migrations run. ojs#5985 adds the line to OJS. OMP and OPS
have no PR, though both already run this table's earlier steps
(`I12048_ReviewRoundAuthorResponse`,
`I12813_UpdateAuthorResponseAndSubmissionCommentTextType`).

## Proposed fix

Tried, in `shared/playwright/checks/sync/pkp-lib-13620/fix.diff`: add

```xml
<migration class="PKP\migration\upgrade\v3_6_0\I13593_AddDateConfirmedAndDateRevertedToReviewRoundAuthorResponses"/>
```

after `I12994_CompetingInterestsDeclared` in OMP's and OPS's
`upgrade.xml`, as pointer-bump PRs beside ojs#5985. With the diff, the 3.5
test press and test server upgrade to 3.6.0.0 with both columns. Tried on
PostgreSQL only.

- **Effort** small

## Summary

`7269eaf6f0` changes how a publication's cover image is saved when
no new file comes with the request: the stored cover is kept, and
only its alt text may change. Creating a version runs that same code a
second time, after the new cover has been moved into place, and at that
moment the stored value is still the request's upload, not the moved
file. So a program that creates a new version through the REST API
with a cover image gets 200 and a version with no cover. The picture
stays in the journal's public folder with nothing pointing to it.

No screen sends a cover with this request. "Create New Version" copies
the current version's cover through another route, which still works.

## Impact

- **Lost**: the cover image sent with the new version. The request
  answers 200 and nothing says the cover was dropped.
- **Who**: programs (an import tool, a migration script, a repository
  integration) that create versions through
  `POST …/submissions/{id}/publications` with a `coverImage`.
- **Way round**: save the cover in a second request, `PUT
  …/publications/{id}` with a new temporary file, which works. The
  orphaned picture can be deleted by hand.

Low: only the REST API reaches it, and the cover can be added
afterwards.

## Steps to reproduce

Preconditions: PKP's default dataset, OJS `main` with `lib/pkp` at
`7269eaf6f0` or later (OMP and OPS once their pointer has it, and
`stable-3_5_0`). Submission 4, "Computer Skill Requirements for New
and Existing Teachers: Implications for Policy and Practice", has one
version. (OMP: submission 3, "The Political Economy of Workplace
Injury in Canada"; OPS: submission 1, "The influence of lactation on
the quantity and quality of cashmere production".)

1. Sign in as `rvaca` and open any page of the journal's settings,
   for example Settings › Website.
2. In the browser's console, upload a PNG as a temporary file and
   create a new version with it as the cover (OMP: `const id = 3` and
   `seriesId` for `sectionId`; OPS: `const id = 1` and
   `versionStage: 'AO'`; 3.5: `version: current.version + 1` and no
   `versionStage`, `versionMajor` or `versionMinor`):

   ```js
   const id = 4;
   const api = pkp.context.apiBaseUrl;
   const headers = {'X-Csrf-Token': pkp.currentUser.csrfToken};
   const get = async (route) => (await fetch(api + route, {headers})).json();
   const current = await get(`submissions/${id}/publications/${(await get(`submissions/${id}`)).currentPublicationId}`);
   const canvas = Object.assign(document.createElement('canvas'), {width: 400, height: 400});
   const png = await new Promise((resolve) => canvas.toBlob(resolve, 'image/png'));
   const form = new FormData();
   form.append('file', new File([png], 'cover.png', {type: 'image/png'}));
   const temporaryFile = await (await fetch(api + 'temporaryFiles', {method: 'POST', headers, body: form})).json();
   const response = await fetch(`${api}submissions/${id}/publications`, {
       method: 'POST',
       headers: {...headers, 'Content-Type': 'application/json'},
       body: JSON.stringify({
           version: 2,
           versionStage: 'VoR',
           versionMajor: 2,
           versionMinor: 0,
           sectionId: current.sectionId,
           title: current.title,
           abstract: current.abstract,
           coverImage: {en: {temporaryFileId: temporaryFile.id, altText: 'Cover'}},
       }),
   });
   const added = await response.json();
   console.log(response.status, added.id, JSON.stringify(added.coverImage));
   ```

3. Open submission 4's workflow, the new "Version of Record 2.0" in
   the "Publication" menu, and look at its cover image; list the
   journal's public folder (`public/journals/1/`).

**Expected**: 200 and the new version with the cover, as until
2026-10-20:

```
200 22 {"en":{"dateUploaded":"…","uploadName":"submission_4_22_coverImage_en.png","altText":"Cover"},"fr_CA":null}
```

**Observed**: 200 and the new version without a cover:

```
200 22 {"en":null,"fr_CA":null}
```

The version has no stored cover, and
`submission_4_22_coverImage_en.png` is in the journal's public folder
with nothing pointing to it. The server log shows nothing. OPS (with
`lib/pkp` at `7269eaf6f0`) and OJS on `stable-3_5_0` show the same.

## Cause

`PKP\publication\Repository::add()` (lib/pkp
`classes/publication/Repository.php`, lines 376-395 at `7269eaf6f0`)
inserts the publication with the request's cover
(`{temporaryFileId, altText}`), then calls `_saveFileParam()` per
language, which moves the temporary file into the public folder and
returns the new value (`{uploadName, altText, dateUploaded}`). It
then saves that value with `$this->edit($publication, ['coverImage'
=> $value])`, and `edit()` calls `_saveFileParam()` again. That second
call has no `temporaryFileId`, so it takes the branch `7269eaf6f0`
rewrote (lines 1150-1161): instead of returning the value it is given,
it returns the value stored on `$publication`. `$publication` is the
row `add()` just inserted, whose cover is still the request's
`{temporaryFileId, altText}` with no `uploadName`, so the branch
returns null and `edit()` stores null.

Reach: `addPublication()` (the REST route above) is the only caller
that passes a new cover to `add()`. `Repo::submission()->add()`
creates a submission's first version without a cover. "Create New
Version" (`POST …/publications/{id}/version`) copies the stored cover,
whose `uploadName` the inserted row already holds, so the second pass
keeps it (code; U49's "Create New Version" tests green on CI with this
commit, Evidence). Editing a version (`PUT …/publications/{id}`)
passes the stored publication, so a new cover saved that way is kept
(walked, the U49 question walk).

## Proposed fix

In `add()`, put the moved value on the publication before `edit()`
runs, so its second pass keeps the file that was just moved:

```php
            // The inserted row still holds the request's temporary file: let edit() keep the moved file
            $publication->setData('coverImage', $value);
            $this->edit($publication, ['coverImage' => $value]);
```

It is in
[fix.diff](https://github.com/jardakotesovec/pkp-e2e/blob/main/shared/playwright/checks/sync/pkp-lib-13561/fix.diff).
Tried on OPS `main` with `lib/pkp` at `7269eaf6f0`: the snippet
answers `200 21 {"en":{…,"uploadName":"submission_1_21_coverImage_en.png","altText":"Cover"},"fr_CA":null}`,
the cover is stored and its file is in the public folder. Neighbour
checks in the same trial (`followup.js` of the 13512 report): the same
request without a cover adds a version without one; with a text file
as the cover it answers 400 as before (that report's finding 3); a
version's cover saved with `PUT` is stored.

**Alternatives**: have `add()` write the cover with
`$this->dao->update()` instead of `edit()`. That skips `edit()`'s
`Publication::edit` hook and event log for this save, which the old
code did run.

**What goes with it**: the value set comes from the server's own move
of the temporary file, never from the request, so the kept-value rule
`7269eaf6f0` introduced still holds. Backport: the same line applies to
`stable-3_5_0` and `stable-3_4_0`. Test: a unit test that adds a publication with a
`coverImage.temporaryFileId` and reads its `coverImage` back.

Small: one line.

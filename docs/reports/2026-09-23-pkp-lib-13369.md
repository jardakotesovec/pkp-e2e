# A journal that does not ask reviewers about competing interests still accepts an empty declaration through the review API and records one

Intention gap. OJS at `802202cb3e` (lib/pkp `5af3b39336`); introduced by
pkp/pkp-lib#13369 (`5af3b39336`, 2026-09-22, for issue
pkp/pkp-lib#13291). OMP and OPS: not yet (their lib/pkp pointers,
`63945bbd82` and `f8bacd7658`, predate the change); the same code will
reach OMP. stable-3_5_0: does not carry the change. Tracked in
`docs/tracking/ci-triage.md` "Open regressions". Temporary: delete once
acted on.

## Summary

Since 2026-09-22 an editor or an API client can record a reviewer's
competing-interests declaration while modifying a review, and the
issue asks for this to be refused on a journal with no
competing-interests policy. A declaration with text is refused there as
asked. A "no competing interests" answer is not: it is accepted and
stored, so the review is marked as declared, with "Competing Interests /
No competing interests were disclosed." in its Review Details and an
activity-log entry, on a journal that never asks the question. Before
the change the same request changed nothing.

## Impact

Only a client that calls the review API with a `competingInterests` key
meets it today. No screen sends that key yet: the Modify Review field is
pkp/pkp-lib#13282, and the issue says that field stays hidden on a
journal without a policy. A journal without a policy can then show a
declaration it never collected. Editors see "No competing interests were
disclosed." in the review's Review Details window. By the code (not driven
here), the public open-review block on the article page and the JATS
peer-review `coi-statement` read the same stored flag. Nothing is lost
and the note is true in wording, but it describes a question the journal
never asked. It also breaks the rule the issue set ("Otherwise return
422"), which the UI and #13282's page config will rely on. Minor:
reachable only through the API today, and the stored value is an empty
declaration rather than wrong data.

## Steps to reproduce

Preconditions:

- A fresh OJS install with its default languages.
- One journal whose Settings › Workflow › Review › "Reviewer Guidance"
  › "Competing Interests" is empty (the default).
- A submission in review, with one reviewer who has submitted a review
  with a recommendation. The reviewer's Step 1 asked nothing about
  competing interests, because the journal has no policy.
- A Journal Manager account with an API key from their profile's
  "API Key" tab ("Create API Key").

1. As the Journal Manager, read the review assignment:
   `GET /index.php/{journal}/api/v1/submissions/{submissionId}/reviewAssignments/{reviewAssignmentId}`.
   Note `reviewerRecommendationId`; `competingInterestsDeclared` is
   `false`.
2. Send a declaration with text (the control):
   `PUT /index.php/{journal}/api/v1/submissions/{submissionId}/reviewAssignments/{reviewAssignmentId}/review`
   with the body `{"reviewerRecommendationId": <as read>, "competingInterests": "some text"}`.
3. Send the "no competing interests" answer, the empty string the issue
   defines for it, to the same address:
   `{"reviewerRecommendationId": <as read>, "competingInterests": ""}`.
4. Read the assignment again as in step 1.
5. In the submission's workflow, open the reviewer's "Read Review"
   (Review Details). Then open "Activity Log".

**Expected** (issue #13291: accept `competingInterests` "only when the
journal asks its reviewers to declare competing interests … Otherwise
return 422"): steps 2 and 3 both answer 422 and the assignment is
unchanged. `competingInterestsDeclared` stays `false`, and Review Details
has no "Competing Interests" section.

**Observed:** step 2 answers 422 as expected:

```
422 {"competingInterests":["Competing interests are not allowed for reviews in this Context."]}
```

Step 3 answers 200. Step 4 reads `"competingInterests": null,
"competingInterestsDeclared": true`, with `lastModifiedById` now the
manager. Review Details reads "Last modified by {manager}" and, under the
guidance paragraph:

```
Competing Interests

No competing interests were disclosed.
```

The Activity Log gains the row "The following was modified in this
review: Reviewer Competing Interests. Select "View changes" to see a
detailed summary of all modifications.". A following
`"competingInterests": null` also answers 200. The review's completion
date, step, round status and the reviewer's task are unchanged.

## Cause

`EditReview::rules()` guards `competingInterests` with
`['bail', 'sometimes', 'nullable', 'string', <closure>]`, where the
closure fails when `Context::isReviewCompetingInterestRequired()` is
false. The API routes run Laravel's `TrimStrings` and
`ConvertEmptyStringsToNull` middleware (`PKPRoutingProvider`), so `""`
and whitespace arrive as `null`. Laravel skips every non-implicit rule
on a `null` value under `nullable`, the closure included, so validation
passes. `ReviewAssignmentController` then sees the key present
(`$illuminateRequest->exists('competingInterests')`) with a value
different from, or a declaration flag not yet set on, the stored one.
It writes `competingInterestsDeclared = true` and logs
`SUBMISSION_LOG_REVIEW_REVIEWER_COMPETING_INTERESTS_MODIFIED`. Before
the change, `EditReview::validated()` did not pass the key through, so
it was dropped.

## Proposed fix

A proposal; the team decides.

1. Check the policy on the key's presence rather than on its value:
   in `EditReview::after()` (or a `withValidator` hook), add the
   "not allowed" error when `$this->exists('competingInterests')` and
   the context has no policy. This covers `""`, `null` and whitespace
   in one place.
2. Or make the closure an implicit rule (an `ImplicitRule` /
   `Rule::when` wrapper), so Laravel runs it on a null value too.
3. As a second guard, the controller could skip the
   competing-interests branch when
   `$context->isReviewCompetingInterestRequired()` is false.

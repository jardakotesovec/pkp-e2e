- **Effort** small
- **Kind** regression
- **Crash** script
- **Affects**

## Summary

A reader who opens a book's PDF from a press's catalog gets the PDF view
page with the viewer's toolbar and an empty grey area under it. No page
of the book is shown, and the toolbar's page count stays blank. The
viewer's own script fails in the browser each time.

The bar's "Download" above the viewer still saves the file, so a reader
who tries it gets the book, but nothing on the page says the viewer has
failed. A press can also turn "PDF.js PDF Viewer" off, after which the
link downloads the file instead.

Every press with a PDF file in a book's formats meets it, since "PDF.js
PDF Viewer" is on by default for a new press.

## Impact

- **Lost**: reading a published book's PDF in the browser, the
  default way a press offers it. Nobody is told: the reader sees an
  empty viewer, and the press sees nothing.
- **Who**: every reader of every press, signed in or not, on every PDF
  file a book's formats hold, from the book page's links.
- **Way round**: the bar's "Download", for a reader who thinks to try
  it; for the press, Settings › Website › Plugins, "PDF.js PDF Viewer"
  unticked.

High: a public surface loses what it is for on every press, with no
message, and the change is meant for the next 3.5 release. It would be
critical if the bar's "Download" failed too.

## Steps to reproduce

Preconditions: the default dataset, OMP `main` (or `stable-3_5_0`).
Its book 5, "Bomb Canada and Other Unkind Remarks in the American
Media", is published with a "PDF" format holding the free file
"epilogue.pdf" under the chapter "Epilogue".

1. Signed out, open the press's catalog and the book "Bomb Canada and
   Other Unkind Remarks in the American Media"
   (`/index.php/publicknowledge/catalog/book/5`).
2. Press the "PDF" link of the chapter "Epilogue".
3. Wait for the PDF view page (tab "PDF view of the file epilogue.pdf")
   to finish loading.

**Expected**: the first page of the PDF under the viewer's toolbar, and
the file's page count ("of 1" for a one-page file) beside the page box,
as before `38bf23300c`.

**Observed**: the toolbar shows with the page box at "1", no page count
and an empty zoom list, and the area under it stays grey. The browser
console reads, for the viewer:

```
Failed to load resource: the server responded with a status of 404 (Not Found)
  …/plugins/generic/pdfJsViewer/pdf.js/build/pdf.mjs
Cannot destructure property 'AbortException' of 'globalThis.pdfjsLib' as it is undefined.
```

The bar's "Download" still answers the file (`200`, `application/pdf`).

## Cause

`38bf23300c` replaces OMP's in-tree copy of PDF.js 2.6.347 with 6.4.299.
It deletes the tracked `plugins/generic/pdfJsViewer/pdf.js/build/pdf.js`
and `build/pdf.worker.js` and adds the new `pdf.js/web/` tree, which is
identical to the one in pkp/pdfJsViewer `8ae9739` (the same update for
OJS and OPS). It adds none of the new build's six files, `build/pdf.mjs`,
`pdf.worker.mjs`, `pdf.sandbox.mjs` and their maps.

They were never added because OMP's `.gitignore` line 3, `build`
(2010), ignores every folder of that name, so `git add` of the plugin
skips `pdf.js/build/`. The old files were committed in 2017 with the
folder already ignored, and stayed tracked until this commit removed
them.

`pdf.js/web/viewer.html` line 37 loads `<script
src="../build/pdf.mjs" type="module">`, and `viewer.mjs` (lines 720,
802) points at `../build/pdf.sandbox.mjs` and `../build/pdf.worker.mjs`.
With `pdf.mjs` missing, `globalThis.pdfjsLib` is never set, and
`viewer.mjs` fails at its first line that reads it.

Reach:

- Every PDF file the viewer opens on a press goes through the same
  frame of `display.tpl` and `viewer.html` (code).
- The release package: `tools/buildpkg.sh` (line 121) builds from a
  `git clone` of the tag, so a 3.5 release cut from `stable-3_5_0` ships
  without the folder too (code).
- OJS and OPS take the plugin as the `pkp/pdfJsViewer` submodule, whose
  repository tracks `pdf.js/build/` at every pointer on `main` and
  `stable-3_5_0` (code; OJS `main` at `8ae9739` carries the six files).
- 3.4 and 3.3: `stable-3_4_0` and `stable-3_3_0` still track
  `build/pdf.js` and `build/pdf.worker.js`, and `pkp/pkp-lib#13615`
  states the update is not ported past 3.5 (code).
- OMP's `display.tpl` (line 51 on) also still loads `build/pdf.js` and
  `web/viewer.js` in the outer page, which now answer 404. That block
  was already dead and is U69 A23 (pkp-e2e#283, "PDFJS is not defined");
  it is not this fault and does not affect the viewer.

## Proposed fix

Commit the six files of PDF.js 6.4.299's `build/` folder into OMP's
`plugins/generic/pdfJsViewer/pdf.js/build/`, the same files pkp/pdfJsViewer
`8ae9739` tracks, on `main` and `stable-3_5_0`. Add a negation to
`.gitignore` so that the next PDF.js update cannot drop them again:

```diff
--- a/.gitignore
+++ b/.gitignore
@@ -1,4 +1,5 @@
 config.inc.php
 .DS_Store
 build
+!/plugins/generic/pdfJsViewer/pdf.js/build/
 temp
```

The negation re-includes only that folder (the other `build` folders
stay ignored), since its parent `pdf.js/` is not itself ignored. This
keeps the intent of `38bf23300c`, the PDF.js update for
`pkp/pkp-lib#13615`, and needs no change to code.

Tried with OJS's `pdf.js/build/` copied into the OMP `main` checkout:
`pdf.mjs` and `pdf.worker.mjs` answered 200, `pdfjsLib` was 6.4.299,
the toolbar read "of 1" and the page was drawn. The `.gitignore` line was
checked on a scratch repository (`git status` lists the folder's files
and still ignores a `build/` elsewhere), not in the app.

**Alternatives**:

- `git add -f` the six files without the `.gitignore` line: it works, as
  the 2017 files did, but the next update repeats this fault.
- Take the plugin as the `pkp/pdfJsViewer` submodule, as OJS and OPS do:
  one copy to update for all three apps. OMP's copy differs (its own
  `display.tpl` and locale files), so that is a larger change, better
  made on its own.

**What goes with it**:

- The same commit on `stable-3_5_0`, before the release that carries
  `dade65f368`.
- U69 scenario 3 ("Opening a free PDF and a free HTML file") is the
  guard and is red today on this fault. No new test is needed.
- Optional, separately: U69 A23's fix (pkp-e2e#283) removes the outer
  page's dead `build/pdf.js` and `web/viewer.js` includes, which now
  answer 404 on every view.

Small: six files copied from the submodule and one `.gitignore` line, on
two branches, with the guard already in place.

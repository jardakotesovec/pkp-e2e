## Summary

The PDF.js 6.4.299 update makes the PDF reader open empty in any browser
that lacks two recent JavaScript features, `Map.prototype.getOrInsertComputed`
and `URL.parse`. The viewer calls both as it starts and the plugin ships
no fallback for either. The reader sees the viewer's toolbar over an
empty grey page, with no page count and no message. With PDF.js 4.10.38
those browsers could read.

By MDN's browser compatibility data, `getOrInsertComputed` arrived in
Chrome and Edge 145, Firefox 144 and Safari 26.2. So the readers hit are
those on Firefox ESR (140 and 128), on Chrome or Edge older than 145,
and on any iPhone, iPad or Mac below Safari 26.2, which includes every
device that cannot take iOS 26. Before the update the oldest browsers
that could read were Chrome 119, Firefox 121 and Safari 17.4.

The reader page's own "Download" link still works.

## Impact

- **Lost**: reading a published PDF in the page, on article and issue
  galleys, for every reader whose browser is older than the versions
  above. Nothing says why the page is empty.
- **Who**: readers of every OJS journal (and of every OMP press, once
  OMP's viewer loads), on managed or older devices: library and
  university desktops on Firefox ESR or a held-back Chrome, older
  iPhones and iPads.
- **Way round**: the "Download" link in the reader page's header, then
  the browser's own PDF reader.

Medium: reading what is published fails for these readers, silently,
but the Download link on the same page gets them the file. It would be
high if the reader page offered no download.

## Steps to reproduce

The fault needs a browser without `Map.prototype.getOrInsertComputed`.
A real one is any of those named above (Firefox ESR 140, for example).
These steps use a current Chrome or Chromium and remove the method
before the viewer loads, which stands in for such a browser.

1. On a fresh OJS install, publish an article with a PDF galley
   (or use any published article with a "PDF" galley).
2. Open a browser that runs `delete Map.prototype.getOrInsertComputed;`
   in every frame before the page's own scripts. A user script manager
   (Tampermonkey, with `@run-at document-start` and `@all-frames`) does
   it in Chrome; the kept script does it with Playwright's
   `addInitScript`. A real Firefox ESR 128 or 140 should need no script
   (not run here).
3. Open the article's page signed out and click "PDF".

Expected (as with PDF.js 4.10.38): the viewer shows page 1, and its
toolbar reads "of 1".

Observed: the toolbar shows with an empty grey body. The page count
box is empty, nothing renders, and the console shows
`TypeError: this[#listeners].getOrInsertComputed is not a function`.

The same happens with `delete URL.parse;` instead: the toolbar reads
"of 0", nothing renders, and the console shows `URL.parse is not a
function`. Without either deletion the same article renders "of 1".

## Cause

The plugin ships PDF.js's "generic" build, which targets current
browsers only. 6.4.299's generic build uses `getOrInsertComputed`
(8 calls in `pdf.js/web/viewer.mjs`, 17 in `pdf.js/build/pdf.mjs`, 16
in `pdf.worker.mjs`) and `URL.parse` (5, 6 and 2). The first call
runs in `EventBus._on` (`viewer.mjs` line 1339), when the viewer
registers its first listener, and `URL.parse` runs in `run()` (line
19283) and `validateFileURL()` (line 20451). The 4.10.38 tree it
replaces (`1d992590f0`) calls neither. PDF.js publishes a "legacy" build
of each release, with these features polyfilled, for older browsers.

## Proposed fix

Ship PDF.js 6.4.299's legacy build instead of the generic one: the
`legacy/build/` and `legacy/web/` folders of the release's
`pdfjs-dist` package in place of `pdf.js/build/` and `pdf.js/web/`, in
pkp/pdfJsViewer (OJS, OPS) and in OMP's own copy, keeping the plugin's
`viewer.html` edits. Re-run the kept script: every variant should
render "of 1". Effort medium, because the build is vendored in two
repos and both lines take it. The other way round, a stated browser
floor in the release notes, keeps the empty reader for these readers.

Not tried: the legacy build was not fetched or served here.

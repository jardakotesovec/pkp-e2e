# Issue assignments (draft)

A working table for trying assignment strategies on the 711 open issues in [jardakotesovec/pkp-e2e](https://github.com/jardakotesovec/pkp-e2e/issues). On GitHub only the issues Jarda Kotěšovec and Kaitlin Newson introduced (their Own) carry an assignee so far (Kaitlin's since 2026-10-07): the inherited ones wait for the balancing to settle, and the other developers cannot be assigned there until they are collaborators on the repository. Generated 2026-10-06 from the issue bodies and the app checkouts' git history; on 2026-10-08 the 13 issues that reported only a missing translation were taken out, #291 follows its narrowed report, and the counts were recomputed from the rows.

**Step 1: own bugs.** The issue's **Introduced** bullet names the author of the change (REPORT.md "Introduced"). When it names a team developer, they take the issue ("Own"); when it names more than one, the first named.

**Step 2: inherited bugs.** An issue whose change came from someone outside the team, or was never traced, goes to a team developer who knows that code ("Inherits"). Alec Smecher (who already owns the most), Jussi Nygård, Jonas Raoni and Dimitris Efstathiou take only their own bugs; the others inherit.

- **Familiarity.** The files the issue's proposed-fix diff touches (translations and tests left out), scored by each inheriting developer's commits to them since 2021: a commit counts half as much every two years back, each file is a share of one vote, and commits touching over 40 files (reformats, migrations, copyright years) and Weblate commits are skipped. With no such commit on the files, the files' folder counts, then its parent, then the files' commits of any year. A fix with no diff, or one that only changes texts, uses the code files its Cause names instead.
- **Balance.** Issues are handed out strongest signal first. Of the developers holding at least 20% of an issue's score, the one with the fewest issues so far (own ones included) takes it, so a clear expert keeps a clear case and a shared area goes to whoever has less. "(balanced)" marks an issue that did not go to its top scorer.
- **Jarda keeps his top scores.** An issue whose top scorer is Jarda Kotěšovec stays with him, never balanced away.
- **Only Alec.** When no inheriting developer has any commit on the code, Alec keeps the issue.

"Area basis" names the level the score came from, the files, and the top three shares.

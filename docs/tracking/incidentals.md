| U65 | Statistics › Reports › "Articles Report" (and, by code, every CSV download: the stats "Download Report" files, Statistics › Users › "Export", the Review, Subscriptions and Monograph reports) | A CSV quoting bug: every writer calls `fputcsv()` with PHP's default escape character `\`, so a `"` that follows `\` in a value is written undoubled. RFC 4180 readers (Excel, LibreOffice, Google Sheets, Python's `csv`) treat `\` as ordinary, end the cell at that `"`, and split the rest of the value into extra cells, so every later column of the row moves under the wrong header, for every reader. Seen with a contributor's given name holding `\"` (`y\",…`): the Articles report's row split into more cells than its header. Fix: pass an empty escape, `fputcsv($fp, $row, ',', '"', '')` (PHP 7.4+, and PHP 8.4 deprecates the default); the writers are `PKPRoutingProvider.php` (`withFile`), `user/Report.php`, OJS `ArticleReportPlugin.php`, `ReviewReportPlugin.php`, `SubscriptionReportPlugin.php`, OMP `MonographReportPlugin.php` (`$output->fputcsv`) | 2026-11-23 | Seen live on OJS stable-3_5_0 (`7f23f05a93`), 2026-11-20, core's Articles report; the other writers by code on main and 3.5 (same `fputcsv` calls).
